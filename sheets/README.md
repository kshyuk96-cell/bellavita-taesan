# 실제 행사장 근거를 사용하는 주문 중복 경고

`DuplicateOrderWarning.gs`는 기존 #32의 편집 경고를 재사용하되 비교 기준을 **배송일 B + 행사시간 C + 보내는 분 요약 Q + 확인된 실제 행사장**으로 바꾼 검토 초안입니다. 설치장소 F가 같은 문자열이어도 실제 행사장 근거가 없으면 중복으로 확정하지 않습니다. 도로명·지번, 단어 순서, 약칭이 달라도 검증된 장소 매핑이 같은 경우를 비교할 수 있습니다.

## 설치 전에 연결할 장소 매핑

아래 콜백은 서버/담당자가 미리 검증한 레지스트리를 사용해야 합니다. `onEdit` 안에서 지도 API·지오코딩·네트워크를 호출하지 않습니다. 모델 추측이나 F 문자열만으로 `resolved`를 만들지 않습니다. 외부 주소 해석기 자체는 이 파일에 포함되어 있지 않습니다.

```javascript
function trustedVenueResolver(input) {
  // input = {row: 123, place: '설치장소 F 값의 공백/표기 정규화 결과'}
  // 승인된 사전 적재 매핑에서만 조회합니다. 이름/주소/연락처를 로그에 남기지 않습니다.
  return {
    status: 'resolved',
    venueId: 'verified-building-or-site-id',
    floor: '3',
    hall: '가상홀',
    wing: '본관', // 선택값: 별관/동 구분이 있으면 검증된 동일 표기로 제공
    evidence: 'approved-registry-version-and-entry-id'
  };
}
```

`venueId`는 검증된 건물/장소 ID이며, 실제 설치 공간은 `floor`, `hall`, 선택값 `wing`(본관/별관/동)을 함께 대조합니다. 두 행의 검증된 ID·층·홀이 모두 같고, 동 구분도 같거나 양쪽 모두 없는 경우에만 `중복 주문 의심`으로 표시합니다. 층·홀·동이 명시적으로 다르면 별개 공간으로 봅니다. 동 구분이 한쪽에만 있으면 `장소 확인 필요`입니다. 층·홀·동은 매핑에서 동일 표기로 정규화해야 하며, 모르는 값을 임의로 채우면 안 됩니다.

여러 후보 또는 장애는 `{status:'ambiguous'|'unavailable'|'unresolved', candidateVenueIds:['검증된 후보 ID']}`로 반환할 수 있습니다. 건물만 같고 층·홀이 없거나 한쪽이 불명확하면 `장소 확인 필요`로 구분합니다. 이 행 쌍 알림도 F가 같은 비어 있지 않은 표기이거나 실제 장소 후보 ID가 겹치는 행에만 한정합니다. 같은 날짜·시각·발신자라는 이유로 모든 미확인 장소를 묶지 않습니다. 다른 표기의 주소가 장애로 해결되지 않고 후보 근거도 없으면 행 쌍을 추정해 표시하지 않고, `장소 조회 미연결/실패로 일부 대조 미완료`를 한 번 표시합니다. `result.unresolved`는 실제 비교에 필요했던 행 중 신뢰 가능한 장소 ID와 근거를 받지 못한 행 수이며, 같은 행을 여러 번 세지 않습니다. resolver가 없거나 예외를 던지는 경우도 포함합니다. 미완료를 중복 없음으로 해석하지 않습니다.

## 기존 편집 처리에 붙이는 위치

사본 Apps Script 프로젝트의 **기존** `onEdit(e)`에서 B/C/F 및 Q 계산이 끝난 다음 `warnDuplicateOrderOnEdit(e, trustedVenueResolver)`를 한 번 호출합니다. 독립 `onEdit` 함수나 별도 트리거를 이 파일이 추가하지는 않습니다. 현행 헤더가 B=배송일, C=행사시간, F=설치장소, Q=보내는분요약인지 먼저 검증합니다. 헤더가 다르면 조용히 검사를 중단하므로 통합 테스트에서 확인해야 합니다.

P의 보내는 분 원문을 받아 Q를 갱신하는 기존 처리라면 원래 P 편집 이벤트만 전달해서는 검사가 실행되지 않습니다. Q 반영 뒤 갱신한 Q 행/범위의 `range`와 같은 `source`를 가진 이벤트를 구성해 한 번 호출합니다. F/B/C도 계산 결과로 갱신되면 그 결과 범위 기준으로 호출합니다. Q 계산 완료 전에 실행하지 않습니다. `SpreadsheetApp.flush()`만으로 외부 지연 계산 완료를 보장한다고 가정하지 않습니다.

API나 다른 스크립트 입력은 편집 트리거를 발생시키지 않습니다. 해당 등록 경로에서 Q 및 장소 매핑 검증이 끝난 뒤 같은 범위 이벤트로 별도 호출해야 합니다. 프로그램 입력 시 toast가 직원에게 실제 표시되는지는 별도 실환경 검증 대상이며 알림 전송이나 원장 기록 완료의 증거가 아닙니다.

한 번의 붙여넣기는 최대 한 번의 toast로 묶고, 고객 정보 없이 행 번호와 `중복 주문 의심`/`장소 확인 필요`를 구분합니다. 편집 100행, 원장 50,000행, 동일 날짜 후보 1,000행, 비교 1,000쌍을 넘으면 확인 미완료를 표시합니다. 이 한도는 대량 붙여넣기에서 무한 비교를 막는 제한이며, 전체 검사를 완료한 것으로 표시하지 않습니다. 빈 날짜·시각·장소·요약과 오류값은 비교하지 않습니다. 시각은 시트 시간대의 초 단위로 비교하며 서로 다른 시각을 같은 것으로 합치지 않습니다.

이 파일은 읽기와 화면 경고만 수행합니다. 원장 쓰기, 실행 트리거 추가, 지오코딩, 고객/직원 발송은 하지 않습니다. 실제 사본의 헤더·Q 재계산·기존 편집 함수·신뢰 가능한 매핑을 연결한 후 검수해야 합니다. 운영 Apps Script 배포 또는 기존 `onEdit` 연결 완료를 주장하지 않습니다.
