# 관리자 반복 업무·인수인계 개선

저장 검색(공유·최대 20개·삭제), 업무별 주문 이력 네 영역, 상품 저장 전 비교와 저장 후 최근 5회 이력, 백업 실패·예정 간격 초과·자동 외부 백업 누락 안내, 고유 주문번호별 인수인계 점검표를 추가했다.

새 관리자 테이블은 기존 SQLite에 추가하며 기존 주문·판매 링크 스냅샷을 변경하지 않는다. 인수인계는 확인 메모로서 결제·배송·제작 승인을 실행하지 않는다. 작성 중 기록 충돌과 주문 상태 변경을 검사하고, 이후 주문·제작·알림·영수증·AS 등이 바뀌면 재확인을 안내한다. 전체 이력은 보존하고 최근 20회만 화면에 표시한다. 백업 검사·복구 보고에 새 테이블 건수를 포함한다.

회귀 144개와 최종 집중 6개가 통과했다. 375/1280px Chromium에서 저장 검색 재접속, 복합 필터, 네 영역 이력, 인수인계 저장, 상품 비교·저장 이력, 백업 안내, 저장 후 위치 유지, 매뉴얼 검색을 확인했다. JavaScript 오류와 가로 넘침은 없었다. 기존 상품 주문서·주문자 동일 체크·긴 문구·서버 가격 계산 및 정정·AS·CSV 배정·정산 흐름도 통과했다.

처음 이력 통합 쿼리의 `checked` 컬럼이 모호해 조회 오류가 났다. 테이블 별칭을 지정한 뒤 같은 이력 조회·인수인계 화면 시나리오를 다시 실행해 해결했다. 실제 결제·실발송·실제 영수증 발급·운영 원장 쓰기는 실행하지 않았다.

서버 배포·재배포 보존 검증 결과는 `docs/validation/shop-admin-workflow.json`에 추가한다. 비밀키·관리자 서명 URL·외부 백업 식별자를 공개 기록에 넣지 않는다.

독립 Render 검증 서버에 `1d55e04` 배포 후 모의 저장 검색과 인수인계 기록을 남겼다. 같은 코드로 다시 배포한 뒤 두 기록과 기존 주문 3건의 결제 대기·취소 상태 보존을 확인했다. 영구 디스크 마운트·SQLite 무결성, 새 관리자 테이블 3개의 백업·임시 복구 건수 대조, 서버 매뉴얼과 원본 일치도 통과했다. 신규 실주문·실결제·실배송은 만들지 않았다.
