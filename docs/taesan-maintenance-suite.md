# 태산이 네 고객 프로젝트 유지보수 — 개발 검토안

## 기준과 범위

승인된 유지보수 10개 묶음이다. 기존 관리 에이전트 PR #53 `25981ca`를 재사용하고 네 고객 프로젝트를 별도 회사·프로젝트 범위로 등록한다. 벨라비타 공통 AI/상거래 PR #56/#57과 독립된 후속이다. main 병합·운영 배포·유료 설정·예약 변경·실제 원장/결제/발송은 하지 않는다.

네 프로젝트의 확인된 개발 위치는 `manager_bridge/maintenance_projects.json`에 있다. 모두 `maintenance_enabled=false`다. 벨라비타 쇼핑몰/협회 Render는 검토 서버로 등록하며, 현재 Sites 주소도 고객 최종 운영 주소로 확정하지 않는다. Sites 소스는 `sites/<정확한 프로젝트ID>`라는 관리 별칭으로 기존 Store의 저장소 범위 검사에 연결한다. 이 별칭은 실제 Git 원격 주소가 아니다. 실제 인증·원격 URL·배포 대상을 연결하는 것은 호스트 책임이며 등록부에 키를 넣지 않는다.

2026-11-15 별도 읽기 점검에서 벨라비타 ERP v20/소스 `2c10b03`, 희망일출 v18/소스 `0a851b3`의 게시 버전과 내려받은 원본 커밋을 대조했다. 당시 ERP 97개 통과/실데이터 fixture 6개 생략, Python 초대장 14개 및 로컬 HTTP 통합, 희망일출 21개와 양쪽 빌드/구문 검사가 통과했다. 이는 해당 시점의 별도 기준선이며 새 소스를 다시 확인하지 않고 현재 건강 상태로 재사용하지 않는다.

## 승인과 실행 경계

`Cycle`은 기존 Store의 정확한 승인 작업을 등록하고 유지보수 바인딩에 소유자 승인을 받는다. 회사·프로젝트 설정, 소스 커밋, 체크 목록, 작업 버전/정책이 달라지면 기존 승인을 사용할 수 없다. 작업자의 보고는 독립 검증이나 배포 승인이 아니다. 실제 독립 검토는 기존 supervisor/review 흐름에 남긴다.

같은 저장소의 일반 개발 작업과 별도 유지보수 시험은 공통 예약에 묶인다. `Store.claim(...,task_id=...)`는 해당 작업만 획득하며 다른 작업으로 대체하지 않는다. 승인된 상위 작업 안에서 시험을 실행할 때 `Checks.run(...,parent_task_id=...)`는 현재 워커 배정·유효한 lease·프로젝트/저장소/커밋·승인된 체크 이름을 매 시험 전후에 대조한다. 상위 작업을 지정해 다른 예약을 우회할 수 없다.

중단·만료·취소·결과 유실은 자동 재실행 허가가 아니다. 불확실한 체크 예약은 보존되며 제공자/프로세스 대조와 신뢰할 복구 절차가 필요하다. `cancel`은 롤백이나 실제 종료를 뜻하지 않는다. `confirm_stopped`는 기존 Coordination의 명세·중단 근거 확인을 사용한다.

`LocalFixtureExecutor`는 비밀값 없는 합성 subprocess 시험용이며 임의 프로젝트 코드를 격리하는 보안 샌드박스가 아니다. 실제 ERP/쇼핑몰 소스는 호스트에 등록된 별도 실행 환경으로 연결해야 한다. 운영 키·고객 DB·쓰기 가능한 Google/PG 권한을 시험 프로세스에 전달하지 않는다. 출력/오류 원문은 이 코어가 보관하지 않는다. 시험 프로세스 성공은 그 안의 모든 개별 업무 사례를 검증했다는 뜻이 아니며 등록된 검증 제공자가 생략·실패를 정확히 구분해야 한다.

DB migration은 등록 SQL만 임시 SQLite 복사본에서 검증한다. D1/PostgreSQL/R2/Google의 실제 백업·복구 검증을 대신하지 않는다. Sheets 비교도 등록 호스트가 권한 있는 원본/제안 사본을 제공해야 하며 실제 API 읽기 성공의 자체 증거가 아니다. 모든 결과는 운영 변경 전 검토용이다.

## 검증 결과

Python 3.12, 전용 임시 TAESAN_DATA와 가상 계정/스킬 비밀값, 등록된 합성 제공자로 전체 463개 시험 통과(기존 246 + 신규 유지보수 217). 로컬 HTTP 시험에 필요한 네트워크 권한을 사용했으며 실제 운영 API는 호출하지 않았다. `git diff --check`와 독립 fixture 실행도 통과했다. 네 프로젝트 로컬 등록부는 모두 비활성화이며 미연결을 정상 상태로 보고하지 않는 것을 직접 확인했다.

## 로컬 실행

```sh
python -m manager_bridge.maintenance --data /private/taesan-maintenance init
python -m manager_bridge.maintenance --data /private/taesan-maintenance inventory --token-file /private/taesan-maintenance/manager.token
python -m manager_bridge.maintenance --data /private/taesan-maintenance inspect --project bellavita-erp --token-file /private/taesan-maintenance/manager.token
python -m manager_bridge.maintenance --data /private/taesan-maintenance report --token-file /private/taesan-maintenance/manager.token
python scripts/maintenance_fixture.py
```

`init`은 새 전용 디렉터리에서만 네 개발 프로젝트와 0600 인증 파일을 만들며 중복 초기화/덮어쓰기/심볼릭 링크를 거부한다. 인증 내용은 출력하지 않는다. 연결 제공자가 없으면 점검 상태는 미연결이며 실행은 비활성화다. CLI 보고는 실제 문자·메일·카톡 전달 확인이 아니다.

`maintenance_fixture.py`는 임시 Git 저장소/가상 자격 범위/가상 SQLite를 만들고 소유자 승인→배정→실제 합성 subprocess 시험→임시 복원/마이그레이션→통합 보고 확인을 실행한다. 실제 프로젝트나 서비스에 접근하지 않는다. source backup 바이트 보존과 비밀값 없는 실행 환경을 확인한다. source fixture의 암호화 여부도 false를 그대로 보고하며 있다고 추정하지 않는다.

## 현재와 다음 단계

이 PR은 대리 관리의 점검·배정·시험·보고 기반이다. 다른 기존 Codex 대화창을 자동으로 읽거나 그 세션을 통제하지 않는다. 실제 소스 인수는 GitHub/Sites 연결을 사용하고 에이전트 지시는 등록된 워커/수신기를 통해야 한다. 현재 대화의 하위 에이전트 분업은 사용했지만 대화 종료 후 모든 에이전트가 상주하는 상태는 아니다.

대표가 범위를 한 번 승인하면 그 안의 일상 개발을 대리인이 처리하는 위임 정책, 기존 Codex 작업 수신기, 프로젝트별 실제 샌드박스/서비스 연결과 운영 승인 묶음은 후속 연결/개발 대상이다. 관리 토큰을 소유자 토큰처럼 사용하는 우회는 하지 않는다. 기존 예약 배포·시간별 자동 개발 설정은 바꾸지 않는다.

AI 실사용 이해/판단/개발 점수는 시험 건수로 올리지 않는다. 새 실제 관측이 없으므로 기준 이해/판단 62.5·개발 75는 유지한다. 가상 프로그램 계약 검증, 실제 모델 관측, 고객 운영 검증을 각각 기록한다.
