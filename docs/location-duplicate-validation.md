# 실제 장소 기준 주문 중복 경고 검토

직원이 원장에 같은 주문을 재입력할 때, 주소 문자열이 달라도 실제 행사장이 같은지 대조한다. 기존 #29의 카카오 조회와 #32의 입력 경고를 이어 만든 별도 후보다. 착수 기준은 main/live `9348afabf049322b2bf3f061d511f5848d7aa1bf`였고, 검토 중 다른 작업에서 main/live가 `9474f6d1d5cd0589ae09c360d90745cbe224d41a`로 갱신되어 최신 main에 재기반한다. 해당 main의 PC 수신 점검 기능을 보존한다. #34→#35→#40→#41, 주문 통합 #37, 쇼핑몰 #20 및 관리/음성 초안은 이 후보에 포함하지 않는다.

## 비교 기준

현재 원장과 기존 테스트 사본의 실제 헤더를 읽기로 대조했다: B=배송일, C=행사시간, F=설치장소, P=보내는분, Q=보내는분 요약. 이 후보는 **B 배송일 + C 행사시간(초 보존) + Q DB 요약 + 실제 행사장 근거**를 사용한다. P 원문으로 Q를 대체하지 않는다. 별도 행사 날짜를 읽었다고 주장하지 않으며, 배송일과 행사일이 다른 업무는 별도 날짜 열 근거 확인이 필요하다. 시트 시간대는 실제 설정을 사용하며 변경하지 않는다.

주소 텍스트·좌표 근접·행사장 이름만으로 같은 곳을 확정하지 않는다. 실제 주소 제공자의 단일 결과와 전체 표준 도로명 주소/반환 별칭으로 건물을 확인하고, 층·홀·본관/별관 등 상세 공간을 별도로 비교한다. 도로명/지번이나 주소·건물명 순서가 달라도 같은 실제 근거와 상세 공간으로 연결되면 중복 의심이다. 같은 건물의 다른 홀·층·관은 별개다. 상세 누락, 복수 장소, 조회 실패, 근거 충돌은 확인 필요다. 누락된 층·홀을 모델이 채우지 않는다.

행 번호를 유지한다. 빈 행과 읽기 실패를 구별하고 주문을 삭제·취소·이동하지 않는다. 매번 최신 원장을 다시 읽는다. 과거 결과를 새 주문 연결의 불변 식별자로 사용하지 않으며, 행 번호 재사용에 관한 다른 기능의 연결 보호는 이 읽기 경고 후보만으로 완성됐다고 주장하지 않는다.

## 구성

- `order_locations.py`: 제공자 근거와 상세 공간을 비교하는 순수 함수. `same`, `different`, `needs_review`와 한국어 사유만 반환.
- `order_location_provider.py`: 서버가 보유한 `KAKAO_REST_API_KEY`로 고정 Kakao 주소 API를 호출하는 요청별 어댑터. 키 미설정, 후보 복수, 부분 주소, 실제 반환 별칭과 불일치, 리다이렉트, 타임아웃/예산 초과는 확정하지 않는다. 법정동 코드 b_code를 건물 ID로 오인하지 않는다. 원문·키·응답 예외를 로그나 영구 캐시에 남기지 않는다.
- `order_duplicates.py` 및 `agent.py`: 기존 직원 인증을 거쳐 “주문 1001번 중복 확인”을 처리한다. 조회 전후 권한을 확인하고 초대장 입력을 보존한다. 결과는 중복 의심과 장소 확인 필요를 구분하며, 읽기 실패를 0건으로 표시하지 않는다. 늦어지면 기존 콜백/결과 보기 경로를 사용한다. 실제 카카오 수신·콜백은 미검증이다.
- `sheets/DuplicateOrderWarning.gs`: 기존 편집 처리기에서 Q 계산 완료 후 호출하는 읽기/toast 경고 함수. 한 번의 붙여넣기는 하나의 경고로 묶는다. 사전 검증된 장소 레지스트리 콜백이 필요하다. 이 파일 자체가 주소 API 호출·셀 쓰기·트리거 설치를 수행하지 않는다. 설치/정규화 계약은 `sheets/README.md` 참조.

서버의 주소 어댑터와 Apps Script의 레지스트리 콜백은 다른 연결이다. 서버 어댑터를 구현했다고 시트의 레지스트리가 자동 적재되지는 않는다. 장소 매핑 갱신/적재와 기존 편집 처리기 연결은 실제 사본 Apps Script에서 확인해야 한다.

## 로컬 재현

Python 3.12와 저장소 requirements.txt를 사용한다. 전용 임시 TAESAN_DATA, 가상 직원과 가상 키만 설정하고 운영 자격증명을 상속하지 않는다.

```sh
python -m unittest discover -s tests -q
node tests/test_sheet_duplicate_warning.cjs
git diff --check
```

Python의 제공자 호출은 주입한 가상 응답이다. 도로명/지번·표기 순서, 서로 다른 공간/시각/DB 요약, 누락·모호·장애, 키 미연결, 요청 예산, 직원 권한 회수, 빈 행, 최신 재조회, 초대장 보존을 검증한다. Node는 가상 SpreadsheetApp/toast/레지스트리이며 실제 시트 편집 이벤트가 아니다.

最新 main `9474f6d`에 재기반한 뒤 Python 전체 **77개**, Node 경고 **9개**가 통과했고 `git diff --check`도 통과했다. 검토 중 지하 3F를 지상 3F와 같게 보던 문제를 수정했으며, 홀 A/B·1/2 등 세부 구역을 버려 같은 장소로 오인하지 않도록 확인 필요로 처리한다. 실제 주소 API 요청과 카카오 기기 시험은 이번 결과에 포함하지 않는다.

## 실제 사본 인수와 적용 조건

대표는 이 기능에 한해 “사본에서 실제 테스트 후 이상 없으면 원장 적용”을 직접 승인했다. **가상 테스트 통과만으로 이 조건을 충족한 것으로 처리하지 않는다.** 다른 개발안·예약 배포 정책 변경으로 범위를 확대하지 않는다.

현재 Sheets 연결로 원장/사본의 메타데이터와 지정 헤더는 읽었으나, Apps Script 소스 조회·수정·실행 도구와 연결된 브라우저가 제공되지 않아 기존 편집 처리기 설치와 네이티브 사본 검증은 미실행이다. 실제 지도 API 키/레지스트리 연결도 미확인이다. 막힌 연결은 추가 개발 승인 문제가 아니다.

연결 후 기존 소스·트리거와 사본 대상 ID를 먼저 확인하고 복구본을 보존한다. 가상 두 주문을 사본에서 입력/붙여넣어 도로명↔지번·앞뒤 순서 변경은 경고, 다른 층/홀/관/시각/요약은 미경고, 장소 장애는 미완료 표시를 확인한다. P 편집 뒤 Q 계산 완료 경로와 API/다른 스크립트 입력도 각각 확인한다. API 입력은 onEdit를 발생시키지 않는다. 검사 중 실제 발송·결제·출력을 유발하지 않는지 기존 트리거를 먼저 점검한다.

그 결과가 통과한 고정 코드와 정확한 변경만 운영에 반영한다. 기존 편집 함수 전체를 추정해 덮어쓰거나 주문 데이터를 사본에서 원장 전체로 복사하지 않는다. 적용 직전 최신 main/live와 기존 스크립트 내용·대상 범위를 재확인하고, 실패하면 새 경고 연결만 복구한다. 현재 main 병합, Render 배포, 운영/사본 셀 쓰기와 Apps Script 변경, 실제 발송은 하지 않았다. 이 초안은 네이티브 사본 검증 전 자동 예약 배포 대상으로 삼지 않는다.
