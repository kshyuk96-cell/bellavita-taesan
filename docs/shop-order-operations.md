# 주문 알림·샘플 이미지·배송·자동 현금영수증

PR #20의 쇼핑몰 주문에 연결한다. 운영 main 병합이나 실제 발송·발급 활성화는 하지 않는다.
체험 화면: https://bellavita-shop-sample.shrewdmaxim1.chatgpt.site
이 주소는 저장소 백엔드에 연결되지 않은 모의 체험용이며 실제 주문·결제·발송·발급이 없다.

## 운영자가 사용하는 흐름

1. 대표 계정의 `쇼핑몰 관리` 화면에서 직원 휴대폰 번호를 저장한다. 번호는 최대 20개다.
2. 페이앱에서 결제 완료 통보를 받은 쇼핑몰 주문을 `주문 확인`으로 만든다.
   이 트랜잭션에서 직원과 주문자별 알림 대기열도 한 번만 등록한다.
3. 같은 주문번호의 저장된 문구·보내는 분·쌀 옵션·설치 정보를 900×1200 JPG로 만든다.
   이미지에는 문구 확인용이며 실제 설치 사진이 아니라는 표시가 들어간다.
   같은 주문의 직원·주문자 알림에는 같은 이미지 바이트가 첨부된다.
4. 직원은 MMS의 24시간 유효 `주문·배송 관리` 링크에서 해당 주문만 관리한다.
   관리 화면에서도 최신 직원용 링크를 다시 열 수 있다. 이 링크는 해당 주문을
   관리하는 권한이 있으므로 담당 직원에게만 전달한다.
5. `배송 중으로 변경` → `배송 완료로 변경`을 누른다. 단계는 건너뛰거나 역행하지 않는다.
   단계 변경마다 직원·주문자에게 이미지 첨부 알림을 등록한다. 실제 수신 완료는
   발송사 조회에서 확인된 후에만 표시한다.
6. 주문자는 결제 후 돌아온 주문 상태 링크에서 같은 주문번호의 진행 상태와 샘플을 확인한다.

대금 미확인 주문은 배송을 시작하지 않는다. 취소·부분취소 통보가 오면 대기 중인
일반 진행 알림과 배송 처리를 보류하고 취소 알림을 별도로 등록한다.
부분취소 주문을 계속 제작·배송할지는 원거래를 대조한 후 별도 정책으로 결정한다.
기존 초대장 주문의 알림·배송·영수증 처리는 이번 범위에 포함하지 않는다.

## 휴대폰 알림 설정

현재 구현한 실제 발송 채널은 **SOLAPI MMS**다. 기존 대표 카카오 `나에게 보내기` 연동을
고객에게 보내는 기능으로 재사용하지 않는다. 카톡 비즈메시지는 별도 채널·승인 템플릿이
필요하며 이번에는 발송 어댑터를 구현하지 않았다.

| 설정 | 의미 |
| --- | --- |
| `SHOP_MESSAGES_ENABLED=1` | 실제 MMS 발송 활성화. 기본은 꺼짐 |
| `SOLAPI_API_KEY`, `SOLAPI_API_SECRET` | 발송 계정 API 정보. 서버 환경에만 등록 |
| `SOLAPI_SENDER` | SOLAPI에서 사전 등록·인증한 발신번호 |
| `SHOP_STAFF_PHONES` | 초기 직원 번호. 관리 화면에서 저장한 값이 있으면 그 값이 우선 |
| `SHOP_PREVIEW_FONT` | 선택 사항. 기본은 저장소에 포함한 Noto Sans KR 글꼴 |
| `TAESAN_PUBLIC_URL` | 고객·직원이 접근할 실제 HTTPS 서비스 주소 |

문자 계정의 사업자·발신번호 인증과 이용 잔액이 필요하다. 테스트 계정·수신 번호로
직원·주문자 각각의 MMS 수신과 첨부 이미지를 확인한 뒤 활성화한다.
직원 번호가 없으면 직원 알림을 생성할 수 없으므로 관리 화면에 미설정 안내가 나온다.
번호 저장 전 과거 주문으로 직원 알림을 소급 발송하지는 않는다.

200KB 이하 JPG를 스토리지 API에 올린 후 MMS로 보낸다. 공급자 접수와 휴대폰 수신 완료는
별개로 기록한다. 통신 오류나 프로세스 중단으로 접수 여부가 불명확하면 `결과 대조 필요`로
남기고 자동 재발송하지 않는다. 발송사에서 주문번호·알림번호·수신번호를 대조한 뒤
관리 화면에서 결과를 기록한다. 확실한 실패만 재요청할 수 있다.

샘플 원본은 `TAESAN_DATA/shop-previews`에 보관한다. 외부 고객 이미지 URL을 서버에서
다운로드하지 않는다. 관리자·고객 화면의 샘플 URL은 주문번호와 만료시각에 결합된 서명을
검사하며, MMS에는 URL 대신 이미지 자체를 첨부한다. 배송 링크와 이미지 링크의 서명은
서로 대체할 수 없다. 기본 이미지 링크는 10분이며 화면 새로고침으로 갱신된다.

## 자동 현금영수증

고객은 주문서에서 소득공제·지출증빙·자진발급을 선택한다. 소득공제 번호를 비우면
주문자 휴대폰을 사용한다. 지출증빙에는 10자리 사업자번호가 필요하다.
카드와 지갑형 간편결제의 별도 현금영수증 발급은 하지 않는다.

자동 발급 조건은 다음과 같다.

- 검증된 결제 완료 통보가 있고 `pay_type`이 6(계좌이체) 또는 7(가상계좌 입금)이다.
- 고객의 현금영수증 신청과 유효한 발급번호가 있다.
- 상품 등록 시 운영자가 과세(TG01) 또는 면세(TG02)를 선택했다. 기본 미설정과
  기존 판매 링크의 미설정 스냅샷은 발급을 보류한다. 과세 구분을 바꾼 경우 새 링크를 발급한다.
- `SHOP_CASH_RECEIPT_ENABLED=1`과 `SHOP_CASH_RECEIPT_OWNER=shop`을 설정했다.
  `shop`은 가맹점에서 **해당 결제를 페이앱/PG가 별도로 자동 발급하지 않음**을 확인하고
  이 백엔드가 발급을 담당하도록 설정한 경우에만 지정한다. 기본값은 발급하지 않는다.
- 기존 `INVITATION_PAYAPP_*` 연동정보가 설정돼 있다.
- 페이앱이 보낸 원결제 시각이 유효하고 공식 API의 발급 가능 기간 안이다.

과세 상품은 총액에 포함된 부가세를 원 단위로 나눠 공급가액·부가세 합이 결제 잔액과
일치하게 요청한다. 면세는 부가세 0원이다. 과세 구분은 상품 운영자가 확인하며 자동 추정하지 않는다.

`cashStRegist` 결과의 발행번호·승인번호·URL을 저장한다. 부분취소가 들어오면 기존
영수증 전체 취소 성공을 확인한 후 남은 금액으로 새 세대를 발급한다. 전체 결제 취소는
기존 영수증도 취소한다. 원거래가 발급 기간을 넘긴 부분취소는 원본 영수증을 유지하고
가맹점 정정 대상으로 보류한다. 발급·취소가 불명확하면 다음 발급을 진행하지 않는다.
대조 후 관리 화면에서 페이앱의 실제 발행번호·승인번호·금액·확인 근거를 기록한다.

신용카드, 카카오페이 머니 등 결제사 발급 거래와 중복 발급하면 안 된다.
가맹점에서 현금영수증 담당 주체, 실제 계좌이체·가상계좌 거래, 발급·전체취소·부분취소
정정과 국세청 반영 결과를 확인한 뒤 운영 활성화한다. 실제 설정이나 사업자 정보를
이 대화에 붙이지 말고 서버 환경 설정에 등록한다.

## 데이터와 장애 복구

기존 SQLite에 `shop_fulfillment`, `shop_stage_history`, `shop_messages`,
`shop_message_checks`, `shop_receipt_payments`, `shop_cash_receipts`,
`shop_receipt_checks`, `shop_notification_settings`를 추가한다.
결제·배송 단계·알림 등록은 같은 DB 트랜잭션에서 처리한다. 워커가 중단된 외부 요청을
서버 재시작 시 불명확으로 복구해 중복 발송·발급을 막는다. 두 워커가 같은 영수증을
동시에 발급하지 않도록 작업을 먼저 원자적으로 선점한다.

백업 도구는 이 테이블과 샘플 이미지 폴더를 함께 보존한다. 기존 영구 디스크 확인과
중지 후 백업·복구 절차는 [쇼핑몰 운영 절차](shop-operations.md)를 따른다.
샘플·연락처·현금영수증 식별번호가 포함되므로 백업과 담당 직원의 접근 권한을 제한한다.

## 재현 검사

```sh
python -m unittest discover -s tests -v
# 별도 터미널에서 serve_shop.py를 실행한 뒤:
SHOP_TEST_DATA=/tmp/bellavita-shop-ops-demo python tests/browser_shop.py
SHOP_TEST_DATA=/tmp/bellavita-shop-ops-demo python tests/browser_order_operations.py
```

검증 서버는 실제 메시지·현금영수증 스위치를 강제로 끈다. 모든 통신 어댑터 검증은
모의 응답이다. 실제 MMS 단말 수신·실가맹점 발급·운영 Render 재배포는 이 검사의 결과로
주장하지 않는다. 정적 샘플 사이트는 앱 화면 체험용이며 백엔드 계정 설정과 연결되지 않는다.
