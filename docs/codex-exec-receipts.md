# Codex 실행 결과를 과장하지 않는 영수증 검사

`inspect_exec_events(events, expected_thread, expected_command=None, process_exit_code=...)`는 등록 호스트가 받은 Codex CLI JSONL 이벤트를 읽기 전용으로 분류한다. 키·파일·네트워크·명령 실행 기능은 없다. 호출자는 먼저 현재 사용자·프로젝트·세션 권한을 확인하고 정확한 세션 UUID와 명령 문자열을 서버 설정으로 제공해야 한다.

| 실제 관측 | 결과 |
|---|---|
| CLI exit 0 + 모델 답변 + turn.completed, 명령 없음 | `dialogue_completed` |
| 검사 명령을 기대했지만 모델이 통과했다고 말하기만 함 | `incomplete` |
| 정확히 등록한 명령의 시작·완료 + exit 0 | `execution_observed` |
| CLI exit 0이어도 내부 명령 exit 1 | `execution_failed` |
| 다른 스레드, 다른 명령, 잘못된 순서·타입 | `unknown` |
| 중간에 끊김·미완료 항목·프로세스/턴 실패 | `incomplete` |

`execution_observed`도 독립 검증은 아니다. 실제 시험 개수·통과 개수는 별도 검증기가 확인하기 전 `None`이다. 모델이나 명령 출력에 적힌 "8개 통과"를 그대로 시험 증거로 바꾸지 않는다. 대화 완료와 전체 계정 Cloud 창 제어도 구별한다.

예상 명령과 실제 전체 문자열은 쉘 래퍼까지 정확히 비교한다. 별칭 추정·쉘 해석·eval을 사용하지 않는다. 이벤트는 최대 2,000개, 직렬화 크기 2 MiB로 제한한다. 원문 질문·모델 답변·명령 출력·명령 본문은 반환 요약에 포함하지 않는다.

실제 합성 연결 로그 4개에 적용한 결과, 첫 요청과 같은 세션 후속 답변은 대화 완료였고 두 검사 요청은 내부 sandbox 설정 실패로 실행 실패였다. 두 검사 모두 CLI 자체는 exit 0이었다. 검사 개수를 관측하지 못했으므로 시험 통과로 기록하지 않았다. 이 분류로 운영 AI 점수를 올리거나 기존 Cloud 창 전체가 연결됐다고 표시하지 않는다.
