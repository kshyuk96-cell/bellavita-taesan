# 범용 합성 QA 계약과 사용법

후속 서버 접수·결과 회수·필수 인수 연결과 실제 주문 코드의 오프라인 검사는 [FOLLOWUP-20261116.md](FOLLOWUP-20261116.md)를 참고한다. 아래 서버 미연결 설명은 PR #72 인계 시점의 범위다.

이 시스템은 프로젝트별 신뢰된 Python 어댑터를 공통 시나리오 계약으로 실행하고, 매니저가 결과를 다시 검증하는 도구다. 기존 `taesan_core`의 `CoreError`, `Principal`, `Order`, `check_fields`와 `manager_bridge.store.digest`를 재사용한다. 기존 업무 평가 점수와 합치지 않는다. 보고서 건수는 AI 능력 점수가 아니다.

## 실행과 결과

```bash
/workspace/taesan-venv/bin/python -m unittest discover -s taesan_core/tests -q
/workspace/taesan-venv/bin/python -m unittest manager_bridge.tests.test_qa_admission -q
/workspace/taesan-venv/bin/python scripts/run_universal_qa.py --seed 20261116 --output /tmp/qa-reproduction
```

실행 소스가 먼저 커밋되어 있어야 한다. CLI는 HEAD의 파일 내용과 실행 파일을 비교하고 원본 SHA-256도 보고서에 남긴다. 생성기는 실행 코드를 문자열로 받아 실행하지 않는다. 네트워크·결제·메시지·운영 주문 변경·프로세스 제어를 호출하지 않는다. 초기 주문 어댑터는 기존 순수 검증/회사 경계 계약만 실행한다. 에이전트 제어와 견적은 별도 메모리 안의 **가상 정책**으로, 실제 매니저 실행 엔진이나 승인된 과금 정책이 아니다.

`run-20261116-contract-bound/summary.json`은 실행 요약과 변이 결함 검출 예다. `scenarios.json.gz`는 시나리오별 입력·예상·실제·판정·증거·위험·상태 근거 전체를 담는다. `scenario-contract.json.gz`는 실행 전 정의된 계약의 내보내기다. 제출된 계약을 그대로 신뢰 계약으로 채택하면 안 된다. `formulas.csv.gz`는 수식별 변수/단위/반올림/예상/실제 결과를 별도로 내보낸다. 압축 파일의 해시와 공통 보고서 해시로 손상을 확인한다. 보고서 해시는 관찰자의 신뢰성이나 독립성을 인증하는 서명이 아니다.

## 공통 API

- `taesan_core.universal_qa.Scenario`: ID, 어댑터, 업무흐름 그룹, 커버리지 키, 위험, 입력, 독립적인 예상값, 오라클 설명, 상태 선택/중복 제거 근거, 선택적 수식 계약.
- `Adapter(name, version, execute)`: 호스트가 등록한 신뢰된 callable. `execute(inputs)`는 `actual`과 비어 있지 않은 `evidence`를 반환한다. 외부 입력을 코드로 해석하지 않는다.
- `run_scenarios(..., source_revision, seed, required_coverage)`: `universal-qa/v1` 보고서. 예상/실제는 JSON 타입까지 엄격하게 비교한다. `true`와 `1`을 같다고 취급하지 않는다.
- `manager_bridge.qa_admission.admit_qa_report(report, expected_source_revision=..., required_coverage=..., expected_contract=...)`: 매니저가 소유한 기대 리비전, 필수 커버리지, 사전에 검토·보관한 시나리오 계약을 전달한다. 보고서 자체 주장으로 그 값을 결정하지 않는다. `build_contract(scenarios, registered_adapters)`로 실행 전에 계약을 구성하고 매니저 소유 저장소에 보관한다. 그 계약은 시나리오 집합과 우선순위·업무흐름·커버리지·위험 근거·어댑터 버전·입력·예상값·오라클·상태키·필수 수식을 묶는다. `expected_contract` 누락 시 차단한다. 보고서의 해시만 다시 계산하여 P0/P1을 P2/P3으로 내리거나 수식을 제거해도 계약 비교에서 차단된다. 반환값 `admitted`는 합성 검증 자료 접수만 뜻하며 `operational_authorization`은 항상 false다. 기존 서버/24시간 호스트에 자동 연결하지 않았다.

버전이나 도메인이 바뀌면 어댑터 버전과 소스 리비전을 갱신하고 새 보고서를 생성한다. 다른 프로젝트는 업무흐름과 오라클을 검토한 후 어댑터를 명시 등록한다. 임의 프로젝트가 자동 검증되었다고 주장할 수 없다.

## 위험과 차단

| 우선순위 | 영향·가능성·복구 판단 | 초기 사례 |
|---|---|---|
| P0 | 회사 경계 침해는 반복 입력 가능하며 노출 후 회수 불가 | 다른 회사 주문 권한 |
| P1 | 잘못된 주문·중복 효과·금액은 경계값/재시도에서 가능하고 수동 복구 필요 | 0 수량, 불확실 실행 재시도, 원 단위 반올림 |
| P2 | 정상 요청 거절은 업무 지연이나 다시 입력하여 복구 가능 | 정상 주문/회사 접근 |
| P3 | 낮은 영향의 진단 조건이며 진단 재실행으로 복구 가능 | 할인 없는 가상 견적 |

각 시나리오에도 영향·발생 가능성·복구 근거가 저장된다. **P0/P1 하나라도 pass가 아니면 차단**한다. 필수 커버리지 누락, 증거/실행/단언 없는 pass, 소스/해시 불일치, 중복 ID, 집계 오류도 차단한다. 많은 정상 건수로 중요한 실패를 상쇄할 수 없다. P2/P3 실패는 경고로 드러내고 삭제하지 않는다.

## 상태·건수·커버리지 해석

- `generated`: 생성된 계약 시나리오 수.
- `executed`: 등록된 어댑터를 실제 호출한 수. 예외도 실행 수에 포함한다.
- `asserted`: 증거가 있는 반환값을 독립 예상값과 실제 비교한 수.
- `pass`/`fail`: 엄격한 예상/실제 비교의 일치/불일치. 예외·잘못된 반환은 `blocked`, 어댑터 미등록은 `unmeasured`다.
- `unique_states`: 어댑터와 전체 의미 입력의 해시 수. 업무 결과 종류나 수학적 모든 등가류를 세었다는 뜻은 아니다.
- `unique_failures`: 어댑터·커버리지·예상·실제 조합의 해시 수. 근본 원인 수가 아니다. 하나의 결함이 여러 불일치로 집계될 수 있다.

기본 시드의 3,006건은 주문 경계 1,000건, 회사/역할 경계 6건, 가상 제어 순서 1,000건, 수식 1,000건이다. 회사 권한에 영향을 주지 않는 주문 금액 변형은 제거하여 역할 3종 × 같은/다른 회사의 6개 등가류만 남겼다. 주문은 숫자 타입/최소/최대와 텍스트 필드/길이의 조합 중 시드 표본이다. 제어는 역할·시작 상태·순서 있는 동작(반복, 취소, 시간초과, 재시도, 검증)을 중복 제거한다. 수식은 0/최대 할인, 중간 할인, 타이, 큰 금액/수량을 포함한다. 각 그룹의 필수 커버리지 키가 모두 있어야 한다. 모든 가능한 조합의 전수 검증은 아니다.

## 오라클과 결함 주입

주문은 SUT의 `check_fields`를 예상값 생성에 호출하지 않고 명시적인 타입/범위/길이 계약으로 예상값을 만든다. 회사 권한은 회사 ID 동일성 계약을 쓴다. 가상 제어 SUT는 조건 분기로, 오라클은 별도의 전이 표로 구현한다. 견적 SUT는 Decimal의 최종 반올림, 오라클은 정수 분자에 5,000을 더한 뒤 10,000으로 나누는 방식이다. 서로 다른 표현도 같은 명세 오류를 공유할 수 있으므로 실제 업무 정책 검토를 대체하지 않는다.

네 결함(`allow_zero_quantity`, `skip_tenant`, `replay_unknown`, `truncate_won`)을 각기 명시적으로 주입하여 전체 시나리오를 다시 실행한다. 정상 구현 통과와 별개로 각 결함에서 실패가 생기고 매니저 접수가 차단되어야 실행이 완료된다. 단순히 고정 pass를 반환하는 테스트가 아니다. 변이 실행은 결함을 의도적으로 가진 가상/검증 어댑터이며 운영 장애를 발생시키지 않는다.

합성 사용자는 실제 사람의 행동/트래픽이 아니다. 실제 UI, 외부 연결, 운영 자료, 실제 에이전트 수행 능력, 24시간 운영은 **미측정**이다. 본 결과로 서비스 운영 완료·실사용자 검증 완료·배포 승인이라고 보고하지 않는다.

## 매니저 연결 시 필수 신뢰 경계

이 배치에는 서버/호스트 연결을 넣지 않았다. 향후 매니저의 **테스트 자료 접수 직전**에 이 게이트를 반드시 호출해야 한다. 매니저가 검토한 계약/커버리지/버전은 작업자 제출물 밖의 저장소에서 읽는다. 제출 보고서나 함께 첨부한 `scenario-contract.json.gz`에서 `expected_contract`를 만들어 전달하는 구현은 금지한다. 계약 변경은 별도 매니저 검토로 승인한 뒤 새 계약으로 테스트를 다시 실행한다. 해시는 내용의 일관성만 증명하며 승인 주체를 증명하지 않는다.

현재 `source_bindings.test_engine_revision`과 `sut_revision`은 같은 저장소 리비전이다. 실제 대상은 저장소 안의 검증 함수와 순수 가상 정책이다. 외부 고객 시스템/SUT 리비전은 미측정이다. 향후 외부 SUT 어댑터는 테스트 엔진 리비전과 별도로 대상 리비전·정책/설정 버전·증거 출처를 매니저가 고정해야 하며, 알 수 없는 대상 버전을 엔진 리비전으로 대신 채우면 안 된다.

`run-20261116/`과 `REPORT-20261116.md`는 초기 소스의 실행 기록으로 보존한다. 현재 신뢰 계약 강화 결과는 `run-20261116-contract-bound/`와 `REPORT-20261116-contract-bound.md`를 사용한다. 두 보고서 모두 합성 자료이며 운영 승인 자료가 아니다.
