## 검증

Python 3.12, 저장소 requirements.txt, 임시 TAESAN_DATA, 가상 계정·키·모의 제공자만 사용했다. unittest 전체 **222개**, Node 중복 경고 **9개**, `git diff --check` 통과. 판단 벤치 4개 테스트가 포함한 **100문항(의도/범위/맥락/근거 각 25문항)**도 별도 재현해 통과했다. 100문항을 222개에 별도 합산하지 않는다.

통합 시험에서는 실제 dispatch·SQLite·ThreadPoolExecutor·로컬 HTTP를 사용하고 외부 제공자는 모의 응답으로 고정했다. 도로명/지번과 다른 공간, 행 재사용, 사유/권한/만료, 대량 청크와 변경 중단, 동시 버튼·다른 조건, 대기/실행 중 취소, 늦은 콜백, 루트 세션 저장 원자성, 사진 원문 비저장, 실제 읽기 재시도, 연결 진단, 실패 관측·실제 가상 재생, 조건 버튼·다른 직원·자정·같은 시각 순서 경계를 확인했다.

검토에서 발견한 대기 Future의 CancelledError, 실패 후 조건 소실, 자정 완료 시 날짜 오표시, 다른 직접 업무 뒤 옛 맥락 재사용, 같은 시각 새 맥락 차단, 새 분할/진단 작업의 권한 회수 누락을 수정하고 회귀시험으로 남겼다.

## 남은 실환경 연결과 운영 조건

실제 카카오 사진+질문 수신/모델 인식, 개발 채널 버튼·콜백, 네이티브 시트 입력/붙여넣기 toast, 실제 제공자·불변 표식 열, 회사 PC 상태 연결은 미검증이다. 개발용 격리 서비스와 사본·Apps Script 편집/실행 연결이 필요하다. 기존 원장/사본의 열 이름 읽기 확인은 실제 편집 이벤트 검증을 대신하지 않는다.

포함된 #41의 권한 변경도 운영 검토 대상이다. 일반 staff 계정은 재고 조회만 가능하며, 입고 등록은 명시적인 입력과 writer/admin 권한을 모두 요구한다. 실제 직원 권한을 변경한 것은 아니며 출시 전에 해당 차이를 대표에게 확인해야 한다.

#43 중복 경고에 대해 대표가 이미 준 “사본 실제 검증 후 이상 없으면 원장 적용” 조건은 유지한다. 이 10개 전체로 운영 승인을 확대하지 않는다. 새 묶음은 정확한 HEAD·범위·실환경 검증과 운영 적용 승인을 별도로 확인한다. 현재 main 병합, Render 배포/설정 변경, 운영/사본 쓰기·실제 발송·실제 결제·출력은 하지 않았다. 시간별 자동 개발과 시트 점검은 중지 상태를 유지하며 기존 9시 배포/주말 배정 정책도 바꾸지 않았다. 네이티브 인수가 끝나지 않은 이 초안을 자동 예약 배포 대상으로 삼지 않는다.

새 운영 실측이 없어 최초 운영 기준 사고 62.5·대처 62.5·개발 75점과 직전 대비 0을 유지한다. 목표 90점은 실제 업무 인수 시험으로 입증해야 한다.
