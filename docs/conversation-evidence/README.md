## 실제로 확인한 범위

`native-text-result.json`은 정답이 없는 공개 입력 50개씩을 서로 분리된 네이티브 개발 에이전트(`/root/conversation_blind_first`, `/root/conversation_blind_last`)에 전달하고 주 관리자가 채점한 결과다. 의도·조건·맥락·근거 각 25/25이며 실행/완료 주장 0개다. 고정 카탈로그 해시는 `ad1b90560acc41a5e44fd3d430ea4630579632576921bc380613b82c6a45d307`이다. 정확한 모델 ID는 확인하지 않았다.

이 시험은 **합성 텍스트 계획 분류**이며 실제 도구나 음성·사진 인식기를 호출한 성적이 아니다. 그 뒤 기록된 읽기 제안을 등록 모델 응답처럼 재생해 실제 대화 엔진·권한·필터·사업별 어댑터에 통과시켰다. `read-plan-replay.json`의 65/65는 이 별도 서버 경계 시험이다. 실시간 모델 대화를 65번 실행한 결과가 아니다.

서버 통합 시험에는 같은 요청 중복, 만료 후 재실행 금지, 다른 사용자·대화·프로젝트 분리, 모호한 완료 상태, 미연결/0건, 철회된 인증과 캐시, 소스 설정 변경, 등록 모델의 잘못된 도구, 사진+현재 질문, 음성 읽기/승인 구별, 원문/바이트 비저장, 실제 루프백 HTTP와 불투명 첨부 참조를 포함한다.

## 인증·실행 계약

`ConversationGateway(store, registry, adapters, core_store, planner=None, media=None, authorize=None, fixture_mode=False)`를 서버에서 등록한다. 기본값에서는 고객 인증 연결이 없으므로 업무를 실행하지 않는다. `authorize(token, project, channel, conversation)`는 현재 사용자와 그 대화에 대한 접근을 매번 검증해 정확히 True를 반환해야 한다. 관리자 토큰 자체를 고객 직원 인증으로 간주하지 않는다. 이 콜백은 캐시 응답 전에도 실행된다. `fixture_mode=True`는 임시 모의 시험용이며 결과에 표시한다.

`planner`는 검토된 제한 규칙 또는 호스트 등록 모델 콜백이다. 응답에는 `rules`/`registered_model` 경로를 표시하며 등록됐다는 사실을 모델 실측·운영 인증으로 간주하지 않는다. 모델은 읽기 Plan만 제안하고 권한·승인·실행 결과를 만들 수 없다. 날짜·센터·집계 등 지원되지 않는 조건을 조용히 버리고 조회하지 않는다. 행사 원장 쓰기·취소·결제·발송 도구는 대화 레지스트리에 없다. 기존 회사별 주문 쓰기 모듈은 재사용 소스 안에 있지만 이 연결에서 등록하거나 활성화하지 않았다.

`CoreStore`와 관리 DB에는 비공개 권한으로 구조화된 조회 조건·결과와 요청 지문만 둔다. 질문 원문·미디어 원본·해석 원문은 저장하지 않는다. 결과 보관 기간이 지나면 상세 응답을 지우고 재실행 방지 영수증을 유지한다. 새 업무나 무효 확인 질문은 이전 조회 조건을 지우며, 누락 부고 번호를 묻는 검증된 읽기 초안은 필요한 필드만 이어 받는다.

## HTTP 연결

기존 인증·JSON·CSRF 경로의 `POST /v1/representative/runtime/conversation/read`를 사용한다.

필수 필드는 `project, channel, conversation, request_id, text`이고 채널은 erp/shop/kakao/manager다. 선택 `attachment_ids`는 1~5개 불투명 참조만 받는다. 서버에 `conversation_gateway`와 `conversation_media_loader(token,project,channel,conversation,ids)`를 등록한다. 수신기는 현재 사용자·대화 권한과 동의를 확인한 `Attachment` 튜플만 반환해야 한다. URL·로컬 파일 경로·역할·승인값·모델 설정·실행 코드를 요청으로 받지 않는다. 첨부 ID가 있더라도 수신기나 인식기 연결이 없으면 글로 다시 요청한다.

현재 서비스 인증·STT·이미지 인식·카카오 실기기 연결·운영 진입점은 설치하지 않았다. 키 생성·유료 호스트·예약·원장·결제·발송 변경도 없다. 실제 연결 때는 기존 AI 게이트웨이를 먼저 재사용하고 비공개 자격 연결 및 배포 후보를 한 묶음으로 검토한다.

## 점수와 복구

운영 기준은 이해 62.5·판단 62.5·개발 75를 유지한다. 텍스트 실험실 100점과 코드 회귀를 운영 AI 점수로 합산하지 않는다. 되돌릴 때는 새 대화 진입점을 끄고 비공개 요청 상태를 보존해 대조한다. 불확실한 요청을 자동 재생하거나 이전 고객 서비스를 바꾸지 않는다.

전체 Python 회귀 **1,209개**가 통과했다. 기존 관리 회귀 843개, 원본 그대로 재사용한 공통 코어 회귀 239개, 이번 대화 연결 회귀 127개를 포함한다. 질문 원문·첨부 바이트 비저장과 실제 루프백 HTTP도 시험했다. `git diff --check` 통과.
