# 3단계 개발 관리 구현과 실제 후속 지시 검증

기준: PR68 `fa7c51ee791178b1eca497de3169b2ecee700980` 위의 개발 후보. 2026년 11월 16일 한국시간.

## 확인한 결과

**이 태산이 작업에서 별도 Codex CLI 개발자에게 지시하고, 독립 검토·실제 격리 테스트·태산이 기술 인수를 거쳐 같은 개발자의 다음 개발 업무를 승인한 뒤 실제 실행까지 확인했다.** 이번 대상은 클라우드 작업공간의 비공개 합성 Git 프로젝트와 명시적으로 선택한 CLI 세션이다. 대표가 전에 별도로 만든 UI 테스트 채팅이나 기존 전체 Codex 창을 인수했다는 뜻은 아니다.

| 실제 흐름 | 확인 결과 |
|---|---|
| 별도 CLI 개발자 1차 작업 | `summarize_delivery` 구현, 실제 명령 3개 종료 0, 완료 턴 관측 |
| 독립 코드 검토 | 별도 검토 에이전트가 고정 후보의 요구사항·코드를 검토, pass 기록 |
| 격리된 독립 테스트 | 고정 명령 2개 실제 종료 0, 코드·검사·런타임 해시 대조 |
| 태산이 기술 인수 | 독립 근거를 요구하는 실제 관리 DB에서 accepted, 운영 승인 False |
| 태산이의 다음 개발 승인 | 정확한 부모 후보와 다음 기준 커밋을 대조한 approve_next 실행, 지정 개발자 claim |
| 동일 CLI 세션의 후속 개발 | `pending_indices` 구현, 실제 명령 3개 종료 0, 완료 턴 관측 |
| 후속 후보 재검증 | 별도 의미 검토 pass, 실제 격리 명령 2개 종료 0, 두 번째 기술 인수 |

개발자가 사용한 두 턴의 실제 세션 ID를 내부에서 대조했다. 공개 증거에는 세션 ID 대신 해시만 남긴다. 상세 증거는 [three-tier-live-evidence.json](three-tier-live-evidence.json)에 있다. CLI 전체 로그·인증·관리 토큰·원문 프롬프트는 Git에 올리지 않는다.

첫 CLI 사전 시험은 수신·명령 실행 가능성을 확인한 별도 시험이었다. 그 결과를 나중에 관리 DB에 소급 등록하지 않았다. 위 관리 작업 두 건은 각각 사전에 승인·담당·임대를 기록한 뒤 실행했다.

## 승인된 10건의 구현

| 항목 | 구현 위치와 동작 |
|---|---|
| 역할과 작업자 등록 | `three_tier.py`: owner만 역할 등록, 프로젝트·현재 인증·기능 권한·설정에 결합 |
| 자기 검토 차단 | 같은 인증 주체의 다른 토큰도 독립 검토자로 허용하지 않음 |
| 검토 전용 하위 임대 | 개발자의 저장소 예약을 유지한 채 별도 검토 임대, 중복 실행 기록으로 동시 재실행 차단 |
| 후보 고정 | 과제 버전·manifest·base/HEAD·변경 경로·산출물·검사 argv·전용 runtime 해시 결합 |
| 독립 실행기 | `three_tier_runner.py`: 실제 Git archive와 추적 blob 대조, 별도 읽기 전용 사본과 namespace에서 고정 검사 실행 |
| 승인 상태 분리 | 개발 보고·검토 통과·태산이 기술 인수 분리. 운영 승인은 항상 별도 |
| 보완·복원 | 최대 2회 보완 후 원인 재분석, 중복 요청 대조, 정확한 검토 정지 근거 없으면 재시도하지 않음 |
| 동시 작업 제한 | 전역·프로젝트별 실행/검토 대기/검토 동시 실행 상한이 없으면 관리 작업 시작 거절 |
| 관리 화면 | `/three-tier`, 한국어 읽기 전용 현황·후보·검사·연결 상태. 현재 검증되지 않은 연결은 표시만으로 승격하지 않음 |
| 대표 결정 보고 | 신규 범위·권한·비용·운영 결정과 태산이가 처리할 보완·차단 항목을 구분 |

개발 과제의 독립 검토는 실제 검사 성공만으로 끝내지 않는다. 정확한 후보와 검토자에 묶인 `CodeAssessment`도 필요하다. 실행기만 등록하고 코드 검토 근거가 없으면 개발 과제의 기술 인수를 거절한다. 의미 검토는 신뢰된 호스트/부모 에이전트가 실제 수행 결과를 등록해야 하며, HTTP에서 pass 불리언을 보내 통과시킬 수 없다.

## 기존 경로 우회 차단

- 관리 대상 프로젝트는 기존 Store.claim으로 미배정 작업을 가져갈 수 없다. 정확한 지정 개발자·현재 설정·필수 상한을 확인하고 관리 상태도 같은 DB 트랜잭션에서 갱신한다.
- 기존 Store.review의 manager_record_only 기록으로 관리 과제를 완료시키거나 저장소를 해제하지 못한다.
- 선행 과제는 정확한 3단계 기술 인수 증거가 있어야 준비 완료로 인정한다.
- 다음 과제는 이미 별도로 승인된 동일 프로젝트·저장소여야 하며, 기준 커밋은 인수한 부모 HEAD와 같아야 한다. 승인 범위를 조용히 늘리거나 오래된 코드에서 후속 작업을 시작하지 않는다.
- 검토자 임대와 개발자 임대의 정지 확인을 혼동하지 않는다. 종료 불명은 대조 상태로 유지한다.

## API와 호스트 연결

기존 인증·쿠키·CSRF·엄격한 JSON 경계를 사용한다. 호스트가 `server.three_tier`에 등록한 서비스만 사용한다. 등록이 없으면 not_configured이며 작업을 시작하지 않는다.

경로: `/v1/representative/runtime/three-tier/`

- POST `members/register`, `limits`, `start`, `development/claim`, `candidate`
- POST `review/claim`, `review/verify`, `review/reconcile`, `decision`, `rework/claim`
- POST `next`, `overview`, `dashboard`
- GET `task?task_id=...`

source_observers·review_hosts·stop_observers는 서버 설정이다. 요청으로 소스 경로·셸 명령·검증 성공 플래그·콜백·제공자를 선택하지 못한다. 관리 화면은 일회용 코드/쿠키 또는 메모리 전용 관리 토큰으로 조회하며 localStorage·URL에 인증을 저장하지 않는다. 운영 실행 버튼은 없다.

## 검증 결과

- Python 3.12 전체 회귀: **1,431개 통과**. 실제 namespace 검사를 실행할 수 있는 승인된 검증 호스트에서 수행했다.
- 실제 namespace 검사를 부모도 독립 재실행해 통과했다. 읽기 전용 소스, 호스트 작업공간·키 비노출, 별도 네트워크 namespace, 실제 파일 생성·두 번째 명령의 내용 대조를 확인했다.
- 자원 상한: NPROC 128, NOFILE 256, FSIZE 256MiB, CORE 0, AS 1.5GiB. 호스트에서 NPROC를 먼저 제한해 namespace 생성이 실패한 문제는 격리를 만든 뒤 내부에서 같은 상한을 적용하도록 수정했다. 상한이나 격리를 제거하지 않았다.
- 기본 명령 샌드박스에서 namespace가 허용되지 않으면 해당 실증 시험은 건너뛰고 이유를 표시한다. 실행기는 이런 경우 일반 subprocess로 대체해 통과시키지 않는다.
- 실제 Chromium 로컬 UI 시험: 인증 조회·입력 토큰 초기화·연결 해제 후 데이터 삭제 확인. 고객 운영 화면이나 기존 Cloud 채팅 제어 시험이 아니다.
- CLI exit 0·턴 완료만으로 통과 판정하지 않았다. 실제 파일·후보·명령 종료·독립 검토와 다음 승인 관계를 확인했다.
- 모델이 출력한 테스트 개수는 사용하지 않는다. 고정 검사 명령 성공과 전체 회귀 테스트 건수는 별도로 기록한다.

## 실제로 남은 범위

이번은 태산이의 도구 실행으로 진행한 합성 프로젝트 실증이다. 상시 관리 데몬을 배포하거나, 고객별 운영 프로젝트·모든 기존 Codex UI 창을 연결하지 않았다. 실제 고객 작업으로 확대하기 전에 프로젝트별 수신기·실행 호스트·검사 프로필·권한·동시 실행 상한을 등록하고 같은 인수 기준을 통과해야 한다.

전용 runtime 폴더의 실제 파일 해시는 고정하지만 `/usr`는 신뢰된 OS 기반으로 사용한다. 전체 컨테이너 이미지 attestation을 완료했다고 주장하지 않는다. 보통 venv의 symlink는 허용하지 않으므로 실제 프로젝트 의존성은 검증 가능한 물리적 runtime 또는 별도 검증 호스트로 준비해야 한다.

별도 OpenAI API 키를 사용하지 않았으며 Codex 구독 사용량은 적용된다. API 키 문제 해결이나 유료 Agents API 연결 완료로 보고하지 않는다. 운영 이해 62.5·판단 62.5·개발 75, 평균 66.7은 유지한다. 이번 관리 기능의 합성 실증을 고객 업무 AI 전체 점수로 바꾸지 않는다.

main 병합·운영 배포·운영 시트 쓰기·실제 결제·발송·키 생성·추가 구매·자동화 설정 변경 없음.
