# 정정 승인·AS·CSV 배정·판매 집계·독립 리허설

PR #20의 관리자 기능이다. 운영 main 병합·실가맹점 거래·실발송·프린터 실행·운영 원장 쓰기는 이 범위에 포함하지 않는다.

## 원주문을 보존하는 정정

결제/부분취소 잔액 대조가 유효하고 배송 시작 전인 주문에서 문구와 보내는 분만 요청한다.
원래 `invitation_orders.details`, 상품/행사/옵션/금액·결제번호·현금영수증 정보는 수정하지 않는다.
정정 요청과 승인/반려는 별도 테이블과 단조 증가하는 결정 번호로 보관한다.

- 검토 중인 요청은 주문별 한 건이며 요청번호 재전송은 같은 내용에서만 멱등 처리한다.
- 요청 즉시 미접수 제작과 문구를 포함한 미발송 알림을 보류한다. 이미 외부로 발송한 메시지를 회수했다고 표시하지 않는다.
- 원문·변경 내용을 대조한 검토자(직접 입력), 근거, 접근 경로, 시각을 저장한다.
- 승인 후 최신 유효 문구/보내는 분은 별도로 계산한다. 새 PNG/PDF를 생성·검수하기 전 제작·배송을 재개하지 않는다.
- 이전 문구 파일은 보존하고, 현재 정정 내용과 다른 이전 승인본임을 화면에 표시한다.
- 반려 시 유효한 기존 제작 승인으로 재개할 수 있다. 취소된 주문의 요청은 반려로 닫을 수 있지만 제작은 재개하지 않는다.
- 결제 취소 알림은 정정 검토 중에도 차단하지 않는다. 승인 시 새 정정 안내와 최신 문구 샘플을 등록한다.

공장 수신기는 `order-amendment-v1` 기능을 선언해야 schema 4 제작 이벤트를 받을 수 있다.
원장의 원주문 스냅샷은 유지하고 제작 내용/승인 파일만 최신 정정 버전으로 갱신한다.
반려에 따른 재개도 현재 결정 번호에 묶는다. 이전 이벤트/ACK가 최신 보류를 풀지 않게 비교한다.
구형 수신기는 보류는 받되 새 정정 제작 이벤트를 받지 않으므로, 실제 연결 전 새 수신기로 검증한다.

## AS·재배송 요청

원주문번호에 종류, 사유, 담당 직원, 처리 근거·사진을 연결한다.
접수 → 배정 → 처리 중 → 해결 → 종결 순서이며, 접수/배정 단계에서 취소 종결도 가능하다.
배정/처리 중은 등록 담당자가 필요하다. 각 변경은 버전 대조 후 감사 이력을 남긴다.
종결 후 기록은 변경하지 않으며 새로운 처리는 별도 요청번호를 사용한다.

추가 사진은 배송 사진과 같은 검증/정규화 기준을 사용하고 AS별 10개까지 보관한다.
관리자용 서명 링크와 해시 검사로 열람하며 고객에게 자동 공개하지 않는다.
AS 상태 변경은 재결제, 제작 접수, 실제 재배송, 출력, 고객 결제 상태를 자동 변경하지 않는다.

## CSV 사전 검토와 승인 배정

관리자 화면에서 UTF-8(BOM 허용) CSV를 업로드한다. 최대 80행·128KB다.

```csv
order_id,event_time,assignee,assignment_version,note
00000000000000000000000000000001,2026-12-20T12:00:00+09:00,등록직원ID,0,배정 근거
```

위 주문번호와 직원 ID는 형식 예시다. 실제 고유 주문번호, 주문 당시 행사 일시, 등록 직원 ID,
현재 배정 버전(미배정 0)을 사용한다. 행사 일시를 변경하는 가져오기가 아니라 일치 여부를 검토하는 배정 기능이다.

사전 검토만으로는 배정하지 않는다. 중복 주문, 없는 주문/직원, 행사 불일치, 취소·배송 완료,
오래된 배정 버전과 잘못된 열을 표시한다. 관리자가 적용 행을 선택하고 확인해야 적용한다.
검토 이후 주문/배정/직원 상태가 바뀐 행은 `stale`로 제외한다.
유효한 선택 행은 한 번만 적용하며 나머지는 invalid/not_selected로 남긴다.
적용한 검토는 다시 사용하지 않고, 다른 행을 적용하려면 새 CSV로 다시 검토한다.
검토 원본 해시, 행별 판정, 관리자 접근 경로, 적용 시각을 보존한다.
결과 CSV는 수식 문자열을 무해화하며 운영 시트에 쓰지 않는다.

## 판매 집계

접수일 기준 주문의 현재 승인원금·취소 누계·잔액·미결제액을 상품 ID, 행사, 주문 당시 쌀 중량으로 묶는다.
세 축 각각의 합계를 기존 주문 정산 합계와 대조한 뒤 화면과 Excel 사본으로 제공한다.
거래일 기준 매출표나 실제 제작 수량/재고 차감으로 표시하지 않는다.
부분취소 금액에서 취소된 쌀 중량이나 제작 수량을 추정하지 않는다.

상품 표시는 현재 상품명임을 명시한다. 신규 링크에는 행사명/상품명 메타데이터를 보존한다.
기존 링크에 분리된 행사명이 없으면 원문 링크명을 그대로 표시하고, 추측해서 이름을 나누지 않는다.
메타데이터 추가만으로 동일 발급 요청에 새 판매 링크를 중복 생성하지 않도록 호환 대조한다.
Excel은 상품/행사/중량과 대조 기준의 네 시트이며, 사용자 문자열은 수식으로 실행하지 않는다.

## 한 명령 독립 리허설

```bash
python tests/rehearse_shop.py --output /tmp/bellavita-rehearsal-new-directory
```

기존 경로는 거절한다. 임포트 단계부터 임시 데이터 경로를 사용하고 상속된 운영 경로·직원 연락처와
발송/백업/원장 활성화 설정을 사용하지 않는다. 외부 urllib 요청은 차단하고 로컬 HTTP 서버와 모의 공급자만 사용한다.

상품 등록/두 가격 링크 → 두 주문/모의 결제 → 모의 현금영수증 → 정정/새 파일 검수 →
공장 파일 접수 → CSV 배정 → 인수/배송 → 사진 공개/고객 확인 → AS 사진/종결 →
중복 부분취소 → 정산/집계 → 모의 알림 → 서버·공장 백업/복구 → 미처리 보류 재개를 재현한다.
결과 JSON, 정산/판매 Excel, 배정 결과 CSV, 서버 스냅샷/복구본, 공장 수신기 복구본을 새 출력 경로에 남긴다.

실제 검증 금액은 승인 192,500원·부분취소 10,000원·잔액 182,500원이다.
복구 후 원문 보존과 고유 공장 주문 두 건, 중복 주문 0건, 미처리 보류 반영을 확인한다.
이 결과는 Render 운영 재배포나 실제 가맹점·단말 검증을 대신하지 않는다.
