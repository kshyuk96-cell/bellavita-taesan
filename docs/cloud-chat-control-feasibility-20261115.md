# 별도 Codex 채팅 연결 가능성 검토 보고서

수신: 강신혁 대표. 작성: 태산이. 기준일: 2026년 11월 15일 한국시간.

## 판정

**태산이가 클라우드 개발 에이전트를 지휘하는 시스템은 구현 가능하다. 그러나 대표가 별도로 만든 ‘태산이의 개발 지시 테스트용 채팅’을 제목으로 찾아 그대로 지휘하는 연결은 현재 미구현이며, 조사한 공식 공개 인터페이스에서 직접 지원 경로를 확인하지 못했다.** 이는 절대 불가능 판정이 아니라, 현재 제공된 도구와 공개 문서로는 지원 및 실제 동작을 입증하지 못했다는 판정이다.

**OpenAI API 키를 연결해도 기존 Codex UI 채팅을 제어할 권한이 자동으로 생기지 않는다.** 키 연결 문제와 별도 채팅 수신 경로 문제는 독립이다. 기존 대화에서는 두 문제를 혼동해 연결 작업의 효과를 과장했고, 이 대화의 하위 에이전트 제어를 별도 UI 채팅 제어와 충분히 구분하지 않았다.

## 요구사항과 현재 상태

| 대표 요구 | 판정 | 현재 증거 또는 남은 조건 |
|---|---|---|
| 태산이 한 명에게 지시하고 하위 작업 배정 | 현재 대화에서 실제 확인 | 하위 에이전트 2명 배정, 후속 지시, 고유 테스트 54개와 루트 재검증 |
| 별도로 만든 특정 UI 채팅에 직접 지시 | 미확인·미구현 | 대상 thread와 수신 서버를 공식 경로로 식별하지 못함. 발송·접수·실행 증거 없음 |
| 관리 대상으로 등록된 개발 세션에 지시·후속 지시 | 공식 구현 경로 있음 | App Server 또는 Agents API 대상 등록·인증·실행 검증 필요 |
| 회사 PC가 꺼져 있어도 클라우드에서 작업 | 구현 가능 | 클라우드 실행 환경과 관리 서비스 필요. PC 상시 실행은 필수 아님 |
| 기존 프로젝트의 유지보수 인수 | 저장소·PR 기준으로 가능 | 대화 전체 인수와 구별. 정확한 저장소·HEAD·운영 커밋·권한·검증 명세 필요 |
| 대화 종료 후 상시 관리 | 현재 미구현 | 지속 실행 관리 서비스·이벤트 수신·재시작 복원·예산·승인 연결 필요 |

위 54개는 위임 프로토콜·디렉터리·XLSX/권한의 테스트다. 반복 실행을 더해 108개로 세지 않으며, 테스트용 UI 채팅 연결의 증거로 사용하지 않는다. 운영 평가 이해 62.5·판단 62.5·개발 75, 평균 66.7은 유지한다.

## 공식 경로 비교

| 경로 | 지원 범위 | 이 요구에 대한 결론 |
|---|---|---|
| Codex App Server | 연결한 서버의 thread/list, thread/resume, turn/start, turn/steer | 등록한 서버의 세션은 제어 가능. 계정 전체 UI 채팅 접근으로 해석할 수 없음 |
| Codex SDK | TypeScript의 로컬 스레드, Python의 로컬 App Server 세션 | 클라우드 VM 안에서 구동하는 작업자 관리에 활용 가능. 기존 UI 채팅 자동 인수 아님 |
| codex queue | UUID 또는 정확한 이름의 세션에 메시지 등록. 실제 재개는 --resume과 실행 중인 daemon 또는 명시한 remote 서버가 필요 | 제목만 안다고 계정의 임의 Cloud 채팅에 보내지는 경로가 아님 |
| codex cloud | 설치 버전 help에서 exec·status·list·apply·diff 확인 | 임의 기존 Cloud 채팅에 후속 지시하는 명령은 확인 못함 |
| Agents API | 관리 세션 생성·후속 입력·이벤트·산출물 회수 | 클라우드 관리 구조의 명확한 공식 경로. 기존 ChatGPT UI 채팅과 자원이 다름 |
| GitHub Codex | PR의 공식 검토 요청과 검토 결과 | 코드 검토에 유용. 특정 UI 채팅 지휘·개발 실행의 증거 아님 |
| 클라우드 브라우저 UI 자동화 | 허용된 브라우저 연결·로그인·origin 승인 아래 UI 조작 | 기술적 검토 후보. 현재 도구 없음·실증 없음. 화면 변경과 중복 제출에 취약 |

공식 근거: [App Server](https://learn.chatgpt.com/docs/app-server), [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk), [CLI 명령](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [Agents API 세션](https://developers.openai.com/api/docs/guides/agents-api/sessions), [GitHub 검토](https://learn.chatgpt.com/docs/third-party/github), [Computer use](https://developers.openai.com/api/docs/guides/agents-api/tools/computer-use).

## 실제 확인한 증거와 한계

검토 기준 코드는 PR66의 `410f374e90e20abec30e0092f3d284a56c0add17`이다. 설치 CLI는 `0.167.0-alpha.4`이며, help를 직접 실행해 명령과 옵션을 확인했다. 독립 검토 에이전트 2명이 공식 문서와 기존 구현을 나누어 검토했다. 이번 검토에서는 새 메시지 발송·유료 모델 실행·환경 생성·배포를 하지 않았다.

- `codex queue --resume`의 help는 재개 실패가 경고로만 나와 명령이 성공할 수 있다고 명시한다. 따라서 프로세스 종료 0은 실제 개발 실행 완료가 아니다.
- 앞선 `codex cloud list --json --limit 20`은 tasks 빈 배열을 반환했다. 이는 해당 인터페이스가 관측한 결과이며, 대표의 전체 UI 채팅이 없다는 뜻이 아니다. 현재 Cloud와 Legacy 통합도 구별해야 한다.
- 현재 도구에 별도 UI 채팅 목록 조회·메시지 발송 기능이 없다. 연결된 문서 제어 도구는 Excel·Word·PowerPoint·Sheets 세션용이며 일반 Codex 채팅 발송 도구가 아니다.
- 현재 환경은 개인용 보관함의 키를 요청하는 설정이 없었다. 다른 환경 설정 작업의 ‘키 전달·51개 테스트’ 인계는 받았지만, 그 결과를 현재 환경의 실제 키 전달이나 게시 완료로 바꾸어 기록하지 않는다.

### 기존 관리 코드의 정확한 의미

| 코드 | 확인 사항 |
|---|---|
| `manager_bridge/session_dispatch.py:3` | ChatGPT Work/Codex 대화창 연결이 아니라고 명시 |
| `manager_bridge/session_dispatch.py:240` | 호스트에 등록한 CLI 세션 UUID로 queue 호출 |
| `manager_bridge/session_dispatch.py:255` | 메시지 등록 후에도 execution_verified는 False 유지 |

따라서 관련 단위 테스트는 승인·범위 제한·비밀 보호·오류 분류를 검증한다. 실제 별도 Codex 채팅이 지시를 받아 실행했다는 검증은 아니다. 앞선 CLI 대화 재개 실험도 별도 Cloud UI 채팅 인수와 다르며, 내부 명령이 sandbox 초기화에서 실패한 시험을 통과 처리하면 안 된다. 보호된 daemon 경로나 격리를 우회하는 해결책은 채택하지 않는다.

## 권고 구조

대표는 태산이와 대화하고, 태산이는 인증된 작업 대기열과 등록된 클라우드 작업자를 통해 실행한다. 작업자에게 저장소·기준 커밋·허용 범위·검증 항목을 전달하고, 산출물과 실제 명령 실행 기록을 받아 독립 검증한다. 대표에게는 승인이나 해결 불가능한 연결만 모아 보고한다.

기존 UI 채팅에서 개발한 자산은 저장소·PR·인계문으로 인수하고, 이후 작업을 관리 대상으로 등록한 세션에 배정하는 방향을 권고한다. 기존 테스트용 UI 채팅을 반드시 그대로 써야 한다면 대상 세션 식별과 허용된 전달 경로부터 별도 실증해야 한다. API 세션 ID와 UI 채팅 ID를 임의로 같은 값으로 취급하지 않는다.

별도 API 키 없이도 현재 대화의 하위 에이전트와, 지원되는 인증을 사용하는 신뢰할 수 있는 CLI 작업자를 검토할 수 있다. 다만 후자는 클라우드 호스트·인증 보호·실행 권한·복원 검증이 필요하며, 현재 환경에서 성공했다고 확정하지 않는다. 공식 비대화형 실행 안내는 ChatGPT 인증을 사용하는 CI/CD 방식을 공개·오픈소스 저장소에서 사용하지 않도록 명시한다. 현재 저장소는 GitHub 조회에서 PUBLIC으로 확인했으므로 이 인증 방식의 CI/CD 자동화를 권고안에서 제외한다. 이는 모든 CLI 사용에 대한 일반 금지로 확대하지 않는다. 근거: [공식 자동화 인증 안내](https://learn.chatgpt.com/docs/non-interactive-mode#authenticate-in-automation). API 경로는 세션과 컨테이너의 별도 비용이 발생하므로 기존 1회·최대 1달러 승인만으로 상시 운영비를 승인받았다고 처리하지 않는다.

## 다음 개발 후보 10건

아래는 개발 권고 목록이며 이번 보고서 작성만으로 전부 착수하거나 운영 반영하지 않는다.

1. 대상 종류를 UI Cloud 채팅·App Server 스레드·Agents API 세션·현재 하위 에이전트로 구분하는 등록 명세.
2. 서버 주소·세션 ID·저장소·소유자·허용 범위를 묶는 인증된 수신기 등록.
3. 등록한 App Server의 thread/list 읽기 연결과 정확한 대상 대조.
4. turn/start·turn/steer의 접수·작업 중·완료·실패 이벤트 연결.
5. 같은 지시의 중복 실행을 막는 요청 ID와 불확실한 결과 대조.
6. 현재 턴과 연결된 실제 파일·커밋·명령 종료 결과의 증거 수집.
7. 루트가 산출물과 테스트를 따로 확인하는 완료 판정.
8. 재시작·타임아웃·인증 철회 시 자동 재실행을 막는 복원 처리.
9. 대표의 개발 승인과 운영 적용 승인을 분리한 변경 범위 검사.
10. 대표용 작업 현황·차단 이유·필요 승인만 모으는 보고 화면.

## 연결 완료의 인수 기준

다음 과정을 하나의 정확한 대상 세션에서 모두 입증해야 한다.

1. 대상 이름뿐 아니라 서버·세션·소유자·저장소를 확인한다.
2. 합성 요청 ID와 nonce가 있는 개발 지시를 전달한다.
3. 대상의 접수 이벤트와 실제 실행 턴을 확인한다.
4. 격리된 테스트 폴더에 합성 파일을 만들고 실제 명령을 실행한다.
5. 같은 세션에 후속 지시를 보내 이전 파일을 수정한다.
6. 태산이가 파일 내용·해시·명령 결과를 독립 검증한다.
7. 다른 대상·중복·만료·권한 철회 시험이 의도대로 차단된다.

기존 UI 테스트 채팅 연결 완료라고 보고하려면 위 대상이 대표가 만든 그 채팅이라는 식별 증거까지 필요하다. 이 대화 안에서 새 하위 에이전트를 생성해 대신 시험한 결과는 대체 증거가 아니다.

## 이번 검토의 완료 상태

공식 문서 조사·현재 CLI 기능 확인·기존 코드와 테스트의 범위 검토·독립 교차 검토를 완료했다. 별도 UI 채팅 연결은 미완료다. main 병합·운영 배포·시트 쓰기·실제 결제·발송·새 키 생성·유료 API 실행·자동화 설정 변경은 하지 않았다.
