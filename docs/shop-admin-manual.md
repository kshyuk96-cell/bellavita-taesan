# 벨라비타 관리자 매뉴얼

화면과 함께 갱신하는 운영 안내입니다. 현재 검증 서버에서는 실제 결제·메시지 발송·현금영수증 발급을 실행하지 않습니다.

## 1. 관리자 화면 열기와 오늘 할 일

1. 대표 카카오에서 ‘쇼핑몰 관리’를 열어 10분 관리자 링크로 접속합니다. 링크가 만료되면 새로 발급합니다.
2. 상단 ‘주문·결제’로 이동합니다. ‘결제 확인 필요’, ‘제작 보류·검수 대기’, ‘배송 대기·진행’ 순서로 확인합니다.
3. 상태 버튼과 빠른 검색은 현재 페이지에 표시된 주문만 좁힙니다. 전체 기록을 찾으려면 아래 ‘전체 주문 검색·필터’를 사용합니다.
4. 주문 요약의 ‘다음 할 일’을 읽고 상세를 펼칩니다. 같은 주문이 여러 확인 항목에 표시될 수 있습니다.

## 2. 주문 찾기

1. ‘전체 주문 검색·필터’에서 주문번호·주문자·휴대폰·보내는 분·문구·상품·행사장을 검색합니다. 휴대폰의 공백·하이픈은 무시합니다.
2. 결제 상태, 배송 상태, 행사 시작일·종료일을 함께 선택할 수 있습니다. 날짜는 접수일이 아닌 행사일입니다.
3. ‘검색’ 후 전체 일치 건수와 현재 페이지를 확인합니다. 한 페이지에 30건까지 표시합니다.
4. ‘조건 초기화’는 검색어와 필터를 해제합니다. 찾는 주문이 없으면 날짜·배송 조건을 먼저 확인합니다.
5. 정확한 주문번호를 알고 있으면 ‘고유 주문번호 조회’를 사용합니다.

## 3. 주문 상세와 링크 복사

1. 주문 요약을 펼쳐 주문자·보내는 분·문구·설치 장소·행사 시간·원결제금액을 대조합니다.
2. ‘주문번호 복사’는 내부 문의용 번호를 복사합니다. ‘고객 상태 링크 복사’는 해당 고객의 주문 상태 주소를 복사합니다.
3. 고객 상태 주소에는 주문 정보가 포함될 수 있으므로 해당 주문자에게만 전달합니다. 직원 배송 링크와 관리자 서명 링크는 고객에게 전달하지 않습니다.
4. 복사가 지원되지 않으면 표시된 읽기 전용 주소를 선택해 직접 복사합니다.

## 4. 결제 확인과 결과 불명

1. ‘결제 요청 확인 필요’ 주문은 페이앱 판매자 거래 현황에서 주문번호·접수 시각·전화번호·원금액을 대조합니다.
2. 결제번호와 확인 근거를 ‘대조 기록 저장’에 남기고 필요한 경우 페이앱 통보 재전송을 요청합니다.
3. 관리자 대조 기록만으로 결제 완료로 바뀌지는 않습니다. 확인된 통보를 기준으로 처리합니다.
4. 결제 요청이 타임아웃되거나 결과가 불명확하면 새 결제를 자동 요청하지 않습니다. 기존 주문을 먼저 확인합니다.

## 5. 제작 검수와 배송 단계

1. 결제 확인 후 문구·보내는 분·설치 정보와 제작 파일을 검수합니다. 족자 실측 규격이 확인되기 전에는 화면 썸네일 비율을 출력 규격으로 사용하지 않습니다.
2. 제작 파일 승인과 결제 조건이 충족되면 ‘배송 중으로 변경’을 실행합니다.
3. 실제 배송을 마친 후 ‘배송 완료로 변경’을 실행합니다. 순서는 주문 확인 → 배송 중 → 배송 완료입니다.
4. 버튼이 없으면 제작 검수·문구 정정·취소·부분취소 대조가 남았는지 ‘다음 할 일’과 상세 안내를 확인합니다.
5. 담당자 배정·인수, 설치 사진 등록·공개·고객 확인은 같은 주문번호에서 관리합니다.

## 6. 취소와 부분취소

1. 실제 취소는 페이앱 판매자 화면에서 실행합니다. 관리자 화면을 닫거나 링크 판매를 중지해도 결제가 취소되지는 않습니다.
2. 원결제금액·취소 누계·남은 금액을 대조합니다. 부분취소로 보류된 주문은 잔액을 확인한 후 재개 여부를 결정합니다.
3. 취소 뒤 늦게 승인 통보가 와도 자동으로 제작·배송을 재개하지 않습니다.

## 7. 상품·가격·옵션 수정

1. ‘상품·판매 링크’에서 상품의 ‘상품 수정’을 펼칩니다.
2. 상품명·기본 판매가·사진·옵션 묶음·선택지 추가금을 수정합니다. 선택지는 ‘옵션명 | 추가금’ 형식으로 한 줄에 하나씩 입력합니다.
3. ‘쇼핑몰에 전시’와 ‘주문 가능’은 다릅니다. 전시 해제는 목록에서 숨기며, 주문 가능 해제는 새 주문을 중지합니다.
4. ‘상품 수정 저장’ 후 고객 쇼핑몰에서 가격과 옵션을 확인합니다. 수정은 새 주문에 적용되고, 기존 주문과 이미 발급한 행사 링크의 조건은 유지합니다.
5. ‘상품이 변경됐습니다’ 오류가 나오면 최신 화면을 열어 다른 관리자의 변경을 먼저 확인합니다.

## 8. 알림과 현금영수증 확인

1. ‘운영 설정’에서 직원 번호·알림톡 필수 설정·템플릿 승인 여부·신규 주문 채널을 확인합니다.
2. 알림 접수와 실제 휴대폰 수신은 다릅니다. 실패가 확인된 건만 재요청하며, 결과 불명은 발송사에서 먼저 대조합니다.
3. 알림톡은 주문별 문구 이미지 확인 링크를 전달합니다. 이미지 파일 첨부형 MMS와 구분합니다.
4. 영수증은 발급 주체·대상 결제수단·상품별 과세/면세를 먼저 확인합니다. 카드·결제사 발급과 중복 발급하지 않습니다.
5. 과세 구분이 빠진 상품이나 발급 결과 불명 주문을 임의로 완료 처리하지 않습니다.

## 9. 정산과 백업

1. ‘정산·집계’에서 대상 기간과 승인·취소·잔액 합계를 확인하고 파일로 내려받습니다.
2. 자동 백업의 최근 결과가 ‘복구 검증 통과’인지 확인합니다. 로컬 백업과 외부 백업은 별도입니다.
3. 현재 외부 암호화 백업은 수동 저장·재다운로드·복구가 검증됐습니다. 매일 자동 외부 업로드 인증은 별도 연결이 필요합니다.
4. 복구는 새 경로에서 검증한 뒤 진행합니다. 기존 운영 DB를 바로 덮어쓰지 않습니다.

## 10. 저장 오류·화면 복귀·인수

1. ‘저장 완료’ 안내가 나온 뒤 기록을 확인합니다. 저장 후 검색 조건과 보던 업무 위치를 유지합니다. 기존 상품을 수정하면 해당 상품의 수정 항목을 다시 펼칩니다.
2. 오류가 나오면 ‘입력 화면으로 돌아가기’로 내용을 확인하고, 오류 원인을 해결한 뒤 한 번만 저장합니다. 결과가 불명확하면 먼저 기존 기록을 확인합니다.
3. 교대 시 주문번호·현재 상태·다음 할 일·대조 근거를 전달합니다. 관리자 링크의 만료 시간을 확인합니다.
4. 매뉴얼 내용과 화면이 다르면 해당 화면 이름·주문번호·재현 순서를 남겨 함께 수정합니다. 실제 연락처나 관리자 링크를 공개 문서에 붙이지 않습니다.

## 11. 저장 검색으로 반복 업무 줄이기

1. 전체 주문 검색에서 조건을 선택하고 검색한 뒤 ‘현재 조건의 이름’을 입력해 저장합니다.
2. 저장 검색은 서버에 보관되며 관리자끼리 공유합니다. 링크 만료 후 새 관리자 링크로 들어와도 사용할 수 있습니다. 페이지 번호는 저장하지 않습니다.
3. 최대 20개까지 등록합니다. 같은 이름을 덮어쓰지 않으며 삭제 후 새로 저장합니다. 고객 이름·전화번호를 검색 조건으로 저장했다면 사용 후 삭제합니다.

## 12. 주문 이력과 인수인계 점검표

1. 주문 상세의 ‘업무별 주문 이력’에서 결제·취소, 제작·정정, 배송·배정, 알림·영수증 기록을 펼칩니다. 항목별 최근 200건을 표시합니다.
2. 알림은 생성 시각과 현재 상태를 표시합니다. 발송사 접수·실제 휴대폰 수신과 구분합니다. 세부 대조·실패 재요청은 기존 상세 기능에서 실행합니다.
3. ‘직원 인수인계 점검표’의 다섯 항목을 확인하고 인계자·인수자·남은 할 일·기한을 기록합니다. 체크는 업무 확인 메모이며 결제·제작 승인·배송 상태를 바꾸지 않습니다.
4. 다른 관리자가 먼저 인수인계를 저장했거나 입력 중 주문 상태가 바뀌면 최신 내용을 확인하고 다시 작성합니다.
5. 마지막 기록 이후 결제·문구·검수·배송·배정이 바뀌면 재확인 안내가 나오며 체크가 해제됩니다. 이전 기록은 보존되고 최근 20개까지 화면에 표시됩니다. 이름 입력은 실명 로그인 인증과 구분합니다.

## 13. 상품 변경 전후 확인

1. 기존 상품의 수정 항목을 입력하고 ‘변경 전후 비교’를 누릅니다. 아직 저장되지는 않습니다.
2. 변경 항목·가격·옵션·전시·주문 가능 상태를 확인한 뒤 ‘상품 수정 저장’을 누릅니다. 다시 입력하면 비교를 새로 실행합니다.
3. ‘상품 저장 이력’에서 최근 5회 변경 전후를 볼 수 있습니다. 이력은 기능 도입 후부터 기록하며 자동으로 되돌리지는 않습니다.
4. 새 상품 수정은 기존 주문·행사별 발급 링크에 반영되지 않습니다. 오래 열린 화면의 저장은 리비전 대조로 막습니다.

## 14. 백업 실패·누락 확인

1. 운영 설정의 ‘백업 누락·실패 안내’에서 최근 로컬 복구 검증 시각과 외부 검증 시각을 확인합니다. 시각은 UTC입니다.
2. 백업 주기와 지연 허용 시간을 넘기거나 최근 실행이 실패·장시간 진행 중이면 안내가 나타납니다. 자동 로컬 백업이 꺼져 있어도 표시합니다.
3. 수동 외부 백업 성공은 자동 외부 백업 성공으로 표시하지 않습니다. 자동 외부 업로드 인증이 없으면 별도 연결이 필요합니다.
4. 안내는 저장된 실행 이력을 기준으로 합니다. 실제 파일·외부 저장소 상태는 복구 검증으로 확인합니다. 이 화면은 파일을 삭제하거나 백업을 강제로 재실행하지 않습니다.

## 15. 행사 빠른 보기

1. 주문·결제의 ‘오늘 행사’, ‘이번 주 행사’, ‘앞으로 7일 행사’를 누르면 전체 주문을 행사일로 검색합니다.
2. 한국 시간 기준이며 이번 주는 월요일~일요일, 앞으로 7일은 오늘을 포함합니다. 링크에 표시된 날짜와 건수를 확인합니다.
3. 빠른 보기는 기존 검색 조건을 초기화하고 취소 주문을 포함한 모든 결제 상태를 보여줍니다. 배송 대상은 결제·검수·취소 상태를 별도로 대조합니다.
4. 매일 새로 열린 관리자 화면에서 최신 날짜를 확인합니다. 저장한 날짜 검색은 고정된 날짜입니다.

## 16. 미처리 업무 담당자와 기한

1. 주문 상세의 ‘담당자·기한 업무 관리’에서 업무명·업무 담당자·한국 시간 기한·남은 일을 입력합니다. 새 업무는 미처리로 등록합니다.
2. ‘미처리 업무’ 현황은 전체 기록의 미처리·기한 초과 건수를 보여주며 기한순 최대 50개를 표시합니다. 전체 주문 검색에서 미처리/기한 초과와 업무 담당자를 함께 검색할 수 있습니다.
3. 기한을 지난 업무도 등록할 수 있으며 기한 초과로 표시합니다. 기한과 같은 분까지는 초과로 표시하지 않습니다. 주문당 미처리 업무는 30개까지입니다.
4. 업무를 펼쳐 담당자·기한·상태·처리 근거를 수정합니다. ‘처리 완료’는 업무 메모의 상태이며 결제·제작·배송을 변경하거나 직원에게 메시지를 발송하지 않습니다.
5. 업무 담당자 이름은 배송 담당 배정·실명 로그인 인증과 구분합니다. 동시에 수정하면 최신 기록을 다시 확인합니다. 변경 이력은 보존하고 업무별 최근 10회를 보여줍니다.
6. 완료 후 현재 검색 조건에서 주문이 사라지면 ‘변경한 주문 바로 열기’로 다시 확인합니다.

## 17. 고객 응대용 주문 요약

1. 해당 주문에서 ‘고객 응대용 요약 복사’를 누릅니다. 복사 기능을 지원하지 않으면 아래 선택된 내용을 직접 복사합니다.
2. 주문번호·상품·원결제금액·결제 상태·행사장·시간·보내는 분·문구·배송 상태를 전달 전에 확인합니다. 승인된 문구 정정이 있으면 그 내용을 사용합니다.
3. 직원 정보·내부 업무/인수인계 메모·고객 전화번호·관리자 링크는 요약에 넣지 않습니다. 해당 주문자에게만 전달합니다.
4. 취소 금액은 확인된 통보 기준이며 원결제금액과 구분합니다. 통보가 없는 이전 기록은 판매자 거래 내역과 대조합니다. 이 기능은 메시지를 자동 발송하지 않습니다.

## 18. 상품·옵션 입력 확인

1. 옵션은 한 줄에 ‘옵션명 | 추가금’으로 입력합니다. 기본 판매가에 옵션 추가금이 더해지므로 최종 금액을 확인합니다.
2. 같은 묶음의 선택지 이름과 옵션 묶음 이름을 서로 다르게 입력합니다. 추가금은 0 이상의 원 단위 숫자이며 기본가와 최대 옵션 금액의 합계는 1억원까지입니다.
3. 입력 안내가 나타나면 해당 줄의 형식·중복·금액을 수정합니다. 묶음을 추가할 때는 이름과 선택지를 함께 입력하고, 최소 한 묶음은 남깁니다.
4. 입력 안내 뒤에도 ‘변경 전후 비교’와 저장 결과를 확인합니다. 서버에서도 같은 이름·최대 금액 등을 검사하며, 잘못된 저장은 기존 상품을 바꾸지 않습니다.

## 19. 직원 교육용 모의 주문

1. 운영 설정의 ‘직원 교육 시작’을 엽니다. 관리자 링크와 같은 권한·만료를 적용합니다.
2. 정상 배송, 결제 결과 불명, 부분취소, 취소 뒤 늦은 승인 통보, 문구 정정과 인수인계의 다섯 사례에서 처리 방법을 선택합니다.
3. 틀린 답은 안내를 읽고 다시 선택합니다. 정답을 확인하면 완료 건수가 늘어나며 같은 사례를 반복해도 중복 집계하지 않습니다.
4. 고정된 가상 데이터로 브라우저 안에서만 연습합니다. 실제 주문·결제·배송·알림·영수증 기록을 만들지 않습니다. 교육 완료는 직원의 실무 권한·승인을 부여하지 않습니다.
5. ‘교육 처음부터’ 또는 새로고침으로 진행을 초기화합니다. 교육 기록은 서버에 저장하지 않습니다.
