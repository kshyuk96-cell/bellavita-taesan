# 중앙 관리 이관과 테스트 개발 분리

테스트 시스템은 `codex/taesan-universal-qa-20261116`의 별도 작업 공간과 작업자에게 맡겼다. 중앙 관리자는 요구사항·접수 기준·검토·프로젝트 이관을 담당한다. 두 작업 공간은 공통 기준 커밋 `3e61925`를 사용하되 변경과 검증 증거를 따로 관리한다. 다른 UI 대화창에 자동 지시했다고 주장하지 않는다. 별도 대화창을 만든다고 계정의 사용 한도나 총 관리 비용이 자동으로 분리되지는 않는다.

## 고객 프로젝트의 실제 소스 대조

GitHub의 지정 브랜치와 Sites의 최신 저장 버전을 읽기 전용으로 확인했다. Sites 저장 버전은 운영 배포 버전과 다르다. 현재 원격 소스와 기존 로컬 사본을 비교했으며 고객 코드를 수정하거나 동기화하지 않았다.

관측 시각·전체 소스 해시·미검증 항목은 [handoff-observation-20261116.json](handoff-observation-20261116.json)에 있다. 이 파일은 해당 시점의 기록이다. 다음 작업 배정 전에는 원격 버전을 다시 조회해야 한다. 읽는 중에도 다른 작업자가 버전을 추가할 수 있으므로 과거 목록을 현재 버전이라고 간주하면 안 된다.

## 다음 이관 순서

1. 변경된 프로젝트는 기존 사본을 덮어쓰지 않고 별도 작업 공간에 최신 소스를 확보한다.
2. 대화에만 있는 결정·미커밋 변경·남은 요구사항을 인계 문서로 묶는다.
3. 프로젝트별 독립 실행 환경과 운영 환경을 구분한다.
4. 별도 QA 작업자가 만든 공통 계약에 업무별 시나리오와 필수 계산식을 연결한다.
5. 승인된 비운영 작업으로 개발→독립 검토→QA 접수→태산이 인수를 검증한다.
6. 그 프로젝트의 후속 지시를 중앙 관리기로 전환한다. 기존 UI 작업자와 같은 수정 범위를 동시에 맡기지 않는다.

`handoff_inventory.inspect_handoff`는 소스 일치·버전 변경·미커밋 변경·조회 불가를 구분한다. 소스가 일치해도 `execution_ready`와 `approval_granted`는 항상 false다. 기존 수정은 보존하며 테스트 실행·운영 변경·작업자 생성은 하지 않는다. 실제 개발 허용은 기존 Registry/ThreeTier/Fleet와 독립 QA 계약의 별도 검증을 거쳐야 한다.

재사용 CLI는 `scripts/inspect_project_handoffs.py`다. 호스트가 읽기 전용 제공자로부터 받은 `SourceHead` 메타데이터, 기존 `SourcePin` 목록, 프로젝트 카탈로그와 소스 사본을 입력한다. 파일 입력은 제공자 인증을 대신하지 않는다. 출력은 소스 목록 밖에만 저장하며 실행 권한으로 사용하지 않는다.
