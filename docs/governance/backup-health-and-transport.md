# Backup health and a private GitHub verification transport

`BackupHealth(EncryptedBackup(...), rehearsal_root=private_root)` is global-owner-only. It records a CAS health policy, checks bounded backup inventory/completion age, and optionally reads the latest ciphertext back through the trusted registered backend and verifies exact length/SHA256. Failed/uncertain backups and unresolved restoration rehearsals require attention. Observer results are rejected if authorization, receipt inventory or policy changes during the read. Retention produces bounded review candidates only; nothing is deleted. A partial inventory never becomes a complete/healthy assertion.

`rehearse(owner, backup_id, request_key)` creates a durable intent before restoring into a fresh private temporary database, measures monotonic elapsed time, then removes the rehearsal copy. Restore quarantine is mandatory. A started/uncertain request key cannot be replayed. This is local component timing, not production RTO. Backup completion age is not measured customer data loss or proven RPO; those values remain unavailable.

`GithubBackupBackend(repository, numeric_repository_id, prefix, authorizer=trusted_owner_callback, client=GhJsonClient())` is an optional dedicated verification adapter. It pins github.com and exact repository identity, requires private/non-archived repository metadata, and uses create-content requests without an existing file SHA, so it never overwrites/deletes a stored file. It authenticates through existing `gh` credentials, without putting credentials in command arguments, results or Git. Data is bounded to 1 MiB per object, Git blob identity is checked, and metadata/owner authorization is rechecked around requests. It is unsuitable for unbounded production control databases; select a scalable object-storage backend before real retention at scale. Owner/admin deletion or repository rollback is outside create-only transport guarantees. Privacy metadata is a point-in-time check, not an atomic guarantee against a simultaneous administrative visibility change.

No backend is configured by default. Public/customer/source repositories are not a fallback target. A dedicated private verification repository could not be created: the existing GitHub integration returned HTTP 403 for the create-repository operation. Repository creation tools and browser-control tools were not available; a supported CLI attempt also failed. No object was uploaded and no private customer repository was repurposed. Protocol tests use a fixture client. Real offsite upload/readback/restore remains pending.

Authenticated operations routes add `backup/report`, `backup/policy` and `backup/rehearse`. All require owner, and the backup implementation additionally requires global owner scope. No endpoint, credential, key provider or destination path can be selected from the request. An unregistered backend/root yields not-configured, not a successful backup.
