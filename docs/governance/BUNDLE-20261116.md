# 중앙 지배구조 개발 묶음

제안 접수→소유자 일괄 승인→클라우드 개발→독립 검토→필수 QA 접수→태산이 기술 인수→승인된 후속 업무 배정을 하나의 중앙 API 흐름으로 연결했다. 테스트 엔진은 별도 개발 결과를 통합했으며 신규 테스트 엔진을 중복 개발하지 않았다. 현재 고객 프로젝트 전체 연결이나 상시 운영 배포 완료를 뜻하지 않는다.

## 구현 범위

| 구성 | 동작 |
| --- | --- |
| ProposalBoard | AI 제안을 정확한 코드·파일 범위·QA 계약·중요도에 묶고 최대 10개를 한 번에 승인 |
| 업무 승인 | 소유자 전용, 정확한 배치 digest, 일부 업무만 승인되는 상태 방지 |
| 소스 감시 | 실행 전 최신 관측 갱신, 300초 내 증거만 사용, 연결 실패 시 마지막 성공 기록으로 승인하지 않음 |
| 필수 QA 게이트 | 제안 기반 업무에는 등록된 계약 필수, 시나리오 우선순위·커버리지 변조나 P0/P1 실패·미검증 차단 |
| 인수 경계 | QA 이후 소스 재대조, 최종 쓰기 시 정책·QA 유효시간 재검사 |
| 계약 버전 | 소유자 CAS로 새 버전 활성화, 이전 버전 기록 보존, 오래된 승인 무효화 |
| 후속 제안 | 미병합 부모라도 실제 인수한 정확한 후보 HEAD를 서버에서 검증해 연결, 원격 소스 기준도 유지 |
| 중앙 서비스 | 인증 HTTP·관리 루프·소스 감시·종료 제어 구성, 누락된 연결은 실행 차단 |

업무 범위 승인과 기술 인수는 다르다. 개발 작업자나 문서의 승인 문구는 업무 승인을 만들지 못한다. 기술 인수가 운영 배포 권한을 만들지도 않는다. 반복 조회나 오래된 배치를 다시 요청해도 현재 소스·계약·권한이 맞지 않으면 실행하지 않는다.

## 실제 합성 실증

비공개 소스·데이터·인증 프로필을 이전 실증과 분리했고 실제 Codex CLI를 사용했다. 소스 관찰자는 명시적인 가상 원격 기준이며 실제 GitHub/Sites 연결로 계산하지 않는다.

| 업무 | 실제 개발 명령 | 실제 격리 검사 | 독립 코드 검토 | 필수 QA | 결과 |
| --- | --- | --- | --- | --- | --- |
| 실제 True 개수 계산 | 5개, 종료 0 | 2개, 종료 0 | pass | 2개 시나리오 접수 | accepted |
| 비어 있지 않고 모두 실제 True인지 판단 | 4개, 종료 0 | 3개, 종료 0 | pass | 2개 시나리오 접수 | accepted |

두 업무 모두 HTTP 제안함과 소유자 배치 승인으로 접수했다. 후속 업무는 부모의 실제 인수 HEAD에 묶였고 태산이의 `approve_next` 기록이 1건 생겼다. 생성 예약은 1건이며 같은 실제 개발 세션이 재개됐다.

이 실증의 QA 두 시나리오는 저장된 실제 격리 검사 종료 코드를 확인한다. 실제 UI·고객 여정 수천 건의 검증이라고 주장하지 않는다. 별도 범용 엔진의 3,006건 합성 시나리오와 결함 주입 결과는 [QA 보고서](../qa/REPORT-20261116-contract-bound.md)에 있다. 실제 프로젝트별 어댑터와 제공자 연결은 추가로 필요하다.

중앙 서비스를 다시 구성해 정상 실행 경로로 2회 감시했다. 개발 영수증 2건·검토 2건·후속 배정 1건과 소스가 유지됐고 추가 실행은 없었다. HTTP 리스너 종료도 확인했다. 이는 24시간 가용성 검증이 아니다.

고정 구현 `c2a324d60e0b923a0a636d531fd7dbcaced48708`에서 전체 테스트 **1,702개가 통과**했다. 실제 namespace와 로컬 HTTP 검사를 포함한다. 독립 검토에서 발견한 오래된 소스 승인, QA 도중 소스 변경, 누락된 QA 정책, QA 유효시간 경과 문제는 회귀 검사로 차단했다.

공개 증거: [bundle-live-evidence-20261116.json](bundle-live-evidence-20261116.json). 세션·업무 식별자는 해시로 기록하며 비밀값·원문 모델 출력은 공개하지 않는다. 과거 결과 불명 작업은 수정하거나 재실행하지 않았다.

## 남은 적용

실제 고객 4개 프로젝트의 유지보수는 활성화하지 않았다. 기존 이관 사본 중 3개는 관측한 최신 소스와 달라 별도 사본에서 갱신·인계해야 한다. [이관 조사](ROLLOUT-20261116.md)를 참고한다.

실제 프로젝트별 QA 제공자와 읽기 전용 소스 연결을 신뢰된 서버에 등록하고, 지속 실행할 호스트·인증 갱신·영속 저장·상태 점검을 적용해야 한다. JSON에 임의 콜백이나 실행 명령을 넣는 방식은 지원하지 않는다. 연결이 없으면 안전하게 멈춘다. [실행 지침](../governance-service-launch.md)과 서비스 예제는 검토용이며 설치·배포하지 않았다.

main 병합, 운영 배포, 운영 원장 변경, 결제·발송, 유료 API 호출과 새 유료 호스트 생성은 수행하지 않았다. 실제 업무 성능 재측정 전이므로 기존 기능 점수 66.7점을 새 테스트 건수로 올리지 않는다.
