# Private migration asset inventory

`inspect_private_state` inspects metadata for explicitly selected paths in ten fixed categories: application checkout, authority database, control credentials, canonical subscription auth, worker subscription auth, host configuration, host access key, trust anchors, recovery keys and evidence catalog. It reads no file contents, invokes no provider and never recursively walks directories. It does not inventory the entire workspace or create a backup.

Private categories require owned physical 0600 files or 0700 directories. Symlinks, hard-linked files, special files, relative/traversing paths and duplicate per-category identities require attention. Path selection is bounded. Unselected categories remain `unconfigured`; missing files are not replaced with substitutes. A metadata-available result does not establish the validity or completeness of any credential, database, source, backup or trust anchor.

The full report contains sensitive filesystem metadata and paths and must remain private. `write_private_inventory` creates an owned mode0600 report exclusively under an owned mode0700 directory and fsyncs file and directory; it never replaces an existing report. `public_summary` omits paths and file metadata. It is for reports produced by this trusted local helper, not untrusted HTTP input. No HTTP route or arbitrary remote file reader is added.

Each category carries a required target-side action. Running SQLite state requires a consistent online backup, not a live-file copy. Source should be recovered from verified pinned repositories. Credentials need explicit encrypted recipient handoff. Recovery keys need independent custody, not inclusion beside the backup that depends on them. Profile registration currently binds filesystem device/inode identity and configuration; copied profiles require explicit owner reconciliation on the target. Host identities and restored authority must also be requalified and quarantined appropriately.

This feature neither transfers credentials nor grants environment replacement, role changes, activation or execution. Keep the original workspace intact until independent restore and target verification succeed. Evidence-directory metadata does not establish that every nested artifact has been selected or preserved. Existing source handoff freshness inspection remains in `handoff_inventory.py`; this inventory addresses private control state rather than replacing source/QA checks.
