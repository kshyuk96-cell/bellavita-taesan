이번 묶음은 실제 고객 소스 4개의 인계 자료와 개발 연결 준비를 만들고, 벨라비타 쇼핑몰의 실제 결함을 별도 사본에서 클라우드 작업자로 수정·독립 검토·후속 지시한 결과다. 고객 운영 유지보수와 상시 호스트 배포는 아직 활성화하지 않았다.

## 실제 고객 코드 수정

[쇼핑몰 수정 PR #78](https://github.com/kshyuk96-cell/bellavita-taesan/pull/78)은 `checkout.py`와 새 회귀 검사만 변경한다.

1. 휴대폰·현금영수증 식별자에서 Unicode 숫자가 ASCII 숫자처럼 통과하던 문제를 수정했다. 기존 ASCII 번호 길이·공백/하이픈·개인 영수증 기본값·자진발급 처리는 유지한다.
2. 실제로 사용하는 고객 텍스트가 문자열이 아닐 때 `AttributeError`/`TypeError` 대신 기존 검증 경로의 `ValueError`를 반환하도록 보완했다. 사용하지 않는 선택 입력은 그대로 무시한다.

실제 수정 전 격리 검사에서 기존 주문 필드 테스트는 종료 0, 고정 Unicode 경계 검사는 종료 1로 결함을 재현했다. 각 개발 업무 후 별도 native 검토자의 코드 검토와 기존 주문 필드 검사·새 회귀 검사·고정 ASCII 경계 검사가 통과했다. 개발 명령 자체의 실패 기록은 숨기지 않았으며 모델 답변이나 프로그램 종료 0만으로 인수하지 않았다.

두 업무는 실제 HTTP 제안→소유자 배치 승인→클라우드 개발→독립 검토→필수 QA→인수로 처리했다. 후속 업무는 인수된 부모의 정확한 HEAD와 같은 원격 기준 계약에 묶였다. 부모 인수는 자식이 소스를 전진시킨 뒤 과거 기록으로 남고, 현재 최종 HEAD의 인수와 구분한다.

이 시험의 원격 소스 관찰자는 명시적인 오프라인 고정 기준이다. 실시간 GitHub 감시·고객 UI·실결제·실발송·운영 원장 검증을 의미하지 않는다. QA 범위도 `synthetic_only` 기계적 검사이며 실제 사업 시나리오 전체 인수로 승격하지 않았다.

## 인증 실패 처리와 복원 격리

첫 환경은 오래된 구독 인증 사본으로 `account/read`에서 실패했다. 모델 실행은 0건이며 해당 불명확 기록과 예약은 보존했다. 같은 업무를 재전송하거나 기록을 초기화하지 않았다. 최근 이미 승인된 성공 프로필을 별도 새 환경에 복사한 뒤 개발·검토 양쪽의 읽기 전용 인증을 확인하고 새 업무를 시작했다. 비밀값을 채팅·Git·명령 인수로 전달하지 않았다.

구독 인증 갱신을 여러 작업자에게 장기간 자동 분배하는 경로는 아직 검증하지 않았다. 감시는 갱신을 요구할 수 있지만 자동 재로그인이나 권한 확대를 수행하지 않는다.

복원 사본은 `governance_restore_marker`에 의해 최신 실행기의 `Store._validate_execution`에서 차단된다. 복원 뒤 대기 업무·실행 중이던 이전 임대·과거 승인·자격은 대조 전 실행 근거로 사용할 수 없다. 과거 작업을 종료됐다고 바꾸거나 자동 재큐잉하지 않는다. 복원 사본은 이 격리 장치를 포함한 최신 실행기로만 다뤄야 하며 이전 바이너리의 안전성을 보장하지 않는다.

## 검증과 남은 조건

구현 커밋 `e270588`에서 전체 테스트 **1,784개 통과**. 실제 namespace와 로컬 HTTP 검사를 포함한다. 독립 검토에서 찾은 Git fsmonitor 실행 가능성과 알려진 인증값의 설정 출력 유출은 회귀 검사로 차단했다. 백업·복원은 전역 소유자만 수행하며 제한된 소유자·관리자가 다른 회사의 DB 전체를 내보낼 수 없다.

[공개 검증 증거](ROLLOUT-PREP-EVIDENCE-20261116.json) · [고객 작업자 인계 패킷](../../manager_bridge/customer-worker-profile-packets.json) · [업무 QA 계획](../customer-qa-requirements.md) · [호스트 결정 준비](CLOUD-HOST-DECISION-20261116.md)

현재 Node 테스트 런타임은 정식 검토 실행기의 크기·이미지 조건을 아직 충족하지 않는다. 별도 namespace 검사에서 읽기 전용 Node 사본을 사용한 희망일출 테스트 통과를 정식 Gate 인수로 계산하지 않는다. ERP의 QR 라이브러리 누락과 협회의 PostgreSQL·브라우저 테스트 환경도 별도 준비가 필요하다.

main/고객 기준 브랜치 병합, 운영 배포, 운영 원장 쓰기, 결제·발송, 유료 API 호출, 새 유료 자원 생성은 수행하지 않았다. 상시 호스트·실제 고객별 전체 QA·구독 인증 장기 갱신이 남아 있어 지배구조 전체 운영 완성으로 보고하지 않는다.
