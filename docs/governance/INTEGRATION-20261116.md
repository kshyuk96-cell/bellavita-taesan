# 고객 프로젝트 연결·상시 관리 준비 묶음

최대 10개 제안 승인 흐름에 고객 등록, 연결 현황, QA 제공자, 업무 배정 진단과 통합 보고를 연결했다. 이 문서의 구현 완료와 실제 고객 운영 연결 완료는 구분한다. 고객 유지보수는 모두 비활성이고 운영 배포는 하지 않았다.

## 승인한 10개 항목

## 실제 확인한 범위

실제 고객 카탈로그 4개와 커넥터에서 읽은 최신 원격 메타데이터를 별도 비공개 관리 DB에 등록했다. 소유자 일괄 등록·관리자 보고·승인 대기 요약·HTML 현황판을 인증된 로컬 HTTP로 호출했다. 정식 서비스 실행 경로로 3회 감시한 뒤 리스너를 종료했다. 개발 업무·검토 업무·자동 실행 동작 기록은 모두 0건이고 원본 4개 소스 사본은 그대로 유지됐다. 이 검증은 고객 운영 DB나 상시 호스트에 접속한 결과가 아니다.

이는 관측 당시의 저장 버전이며 배포 버전과 같다고 단정하지 않는다. Sites 다운로드 오류 뒤 다른 권한 경로로 우회하지 않았다. 관측값은 300초가 지나면 최신 소스 권한으로 사용할 수 없다.

## 검증 로직

- QA 계약은 알려진 원격 기준 커밋과 모든 검사 명령을 개발 전에 고정한다. 미리 알 수 없는 개발 결과 HEAD는 실제 후보·실행 증거·QA 보고에서 따로 대조한다.
- 후속 업무의 기준 커밋이 달라지면 서버에 저장된 정확한 Board 승인과 인수된 부모 증거를 검증한다. 요청 본문에 쓴 부모 식별자만으로 통과시키지 않는다.
- 새 계약은 이전 실행 증거를 소급 인정하지 못한다. 실행 전 저장한 이벤트 순번과 이후 검토 시작 기록을 대조한다.
- 현황판은 외부 소스·QA 확인 뒤 현재 작업 인수 상태를 다시 확인하고, 최종 응답 시 연결·건강 상태 유효시간과 자격을 검사한다.
- 업무 목록은 전역 20건, 인수 최신성 확인은 최대 3건이다. 작업자·호스트·템플릿·복구 목록도 상한과 전체 개수를 표시하고 일부만 확인하면 준비 완료로 판단하지 않는다.
- 승인 배치는 프로젝트당 최근 20건을 확인한다. 오래된 승인 대기가 표시 범위 밖에 있으면 요약을 불완전으로 표시한다. 추가 비용은 승인하지 않으며 비용 추정값은 미측정으로 남긴다.
- 회사 PC, QR 연결 또는 카카오 연결을 클라우드 개발의 필수 조건으로 요구하지 않는다. 프로젝트별 실제 연결 증거가 없으면 미확인으로 남긴다.

기계적 QA 계산식은 `모든 승인 검사 명령의 실제 종료 코드 = 0`이며, 전체 명령 집합·digest·검토 출처가 정확히 일치해야 한다. 시나리오 통과율만 높아도 누락·실패·변조된 필수 검사는 인수할 수 없다. 실제 사업 계산식은 고객별 오라클이 준비되기 전 미검증이다.

## 다음 실제 연결에 필요한 것

Sites 2개의 최신 소스 읽기 경로, 고객별 실행·검토 프로필과 업무 QA 오라클, 영속 클라우드 호스트·보관소·인증 갱신 경로가 남아 있다. 지금 구현은 준비되지 않은 연결을 통과로 가정하지 않는다. 기존 Codex 채팅창 전체를 직접 제어한다는 의미도 아니다.

main 병합, 운영 배포, 운영 원장 쓰기, 결제·발송, 유료 API 호출, 새 유료 자원 생성은 수행하지 않았다. 실제 업무 성능 평가 전이므로 기능 점수 66.7점은 올리지 않는다.
