# 중앙 통제 20개 묶음 — 2026-11-16

목표는 사용자가 태산에게 승인한 개발 범위 안에서 등록된 클라우드 작업자를 배정·검토·후속 지시하고, 필요한 결정만 묶어 보고하는 것이다. 이번 변경은 기존 실행·권한 코어 위에 하나의 인증된 중앙 경로를 연결한다. 기존 임의의 Codex 채팅을 직접 조작하거나 전체 프로젝트의 상시 운영을 완료했다는 뜻은 아니다. 별도 Codex에서 개발 중인 테스터 엔진은 개발·실행하지 않는다.

새 기능은 중앙 경로·20개 원자적 묶음·스캔 창 내 우선순위·연결 계획·통합 보고·외부 테스터 교환 규격이다. 이미 있던 기능을 새 개발 실적으로 중복 계산하지 않는다. 구조화 명세를 태산이 작성하는 단계와 실제 API가 권한을 검증하는 단계를 구분한다. 코드가 임의 목표를 스스로 발명하거나 사용자의 문장을 인증된 소유자 자격으로 바꾸지 않는다.

## 실제 연결 경로

`build_service(..., governance=True)`가 같은 core/store의 `ControlCenter`, `ControlDigest`, `ControlOnboarding`을 등록한다. HTTP는 기존 인증·엄격한 JSON·요청 크기·CSRF 경로를 그대로 사용한다.

POST 접두사: `/v1/representative/runtime/governance/control/`

| 경로 | 정확한 입력 필드 | 효과 |
| --- | --- | --- |
| `bundles/prepare` | request_key, specs | 최대 20개 제안과 하나의 결정 배치 준비 |
| `bundles/get` | batch_id | 정확한 배치와 현재 유효성 조회 |
| `bundles/approve` | batch_id, batch_digest | 소유자만 정확한 배치 전체 승인; 부분 실패 시 전체 롤백 |
| `step` | projects, 선택 limit | 등록된 서비스 instance와 최신 소스 preflight를 거쳐 승인된 작업의 다음 단계 진행 |
| `tasks/get` | task_id | 등록된 호스트 범위의 작업 추적 |
| `report` | projects | 사용자용 통합 요약 |
| `connections/inventory` | projects | 최대 20개 프로젝트의 저장된 연결 현황 |
| `connections/plan` | request_key, projects, expected_bindings | 정확한 registry 바인딩에 대한 연결 계획 저장 |
| `connections/get` | plan_id | 계획 재조회·변경 시 invalidated 표시 |

HTTP에서 instance_id, 실행 명령, 콜백, 인증 파일 경로, sandbox 설정을 선택할 수 없다. `step`은 소스 관찰이 없거나 실패하면 실행하지 않는다. 관찰 콜백 뒤에 요청자 권한과 설정을 다시 확인한다. 서비스 중지 이벤트는 중앙 경로에도 연결된다. 계획과 보고는 실행 승인이나 클라우드 연결 성공을 대신하지 않는다.

## 검증과 실제 운영의 구분

로컬 HTTP에서 20개 준비→소유자만 전체 승인→작업 재조회, 연결 계획 재조회, 한 번의 개발 배정 상태 전이를 확인했다. 이때 개발자는 fixture이며 모델 호출은 없다. 마지막 항목 실패 시 20개 준비/20개 작업 승인이 모두 롤백되는지, 재전송/Store 재구성 후 중복이 없는지 검사했다. 공정 스캔 205개 작업, 우선순위, 검토 우선, 의존성·저장소 예약·한도·불확실 작업의 재시작 격리도 검사했다.

실제 구독 작업자의 이전 개발·검토·후속 개발 증거는 PR 78, 공식 인증 갱신·예약 백업 증거는 PR 82에 있다. 이 변경의 fixture 검증을 새로운 실제 고객 개발이나 상시 배포로 합산하지 않는다. 독립 검토에서 중앙 step의 source preflight 누락을 발견하여 고쳤고 조회 실패/권한 변경 시 실행되지 않음을 별도로 확인했다.

## 90% 통제의 미충족 조건

이 보고서는 임의의 완료율을 계산하지 않는다. 네 고객의 실제 소스·작업자 연결, 신뢰된 상시 호스트의 격리와 영속성, 재시작/복구 실증, 실제 운영 기간의 관찰이 모두 아직 갖춰진 것은 아니다. 기존 Codex 채팅 전체 제어도 확인되지 않았다. `ops/control-launch-preflight.json.example`과 [실행 준비](../control-launch.md)는 초안이며, 추가 지출·운영 배포는 하지 않았다.

별도 테스터가 완성되기 전까지 새 엔진을 대신 만들거나 기존 승인 검사를 끄지 않는다. [외부 교환 계약](../external-tester-contract.md)은 결과를 받을 때의 형식만 정의한다. 향후 실제 테스트 제공자의 인증·현재 후보 바인딩·정책 연결은 공유받을 지시서를 바탕으로 통합한다.
