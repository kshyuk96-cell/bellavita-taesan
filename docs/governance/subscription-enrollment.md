# Owner-authorized subscription target enrollment

`SubscriptionEnrollment(existing_broker).plan(owner, additions, expected_generation)` produces an immutable exact plan. `apply(owner, plan)` returns a **new** `SubscriptionBroker` containing old and added targets. The supervisor must replace its registered broker/guard factories with this returned instance. Old objects fail closed on ownership/binding checks; they are not silently upgraded.

This is a trusted Python host capability, not an HTTP client-controlled credential distribution endpoint. Only already registered owner-scoped developer/reviewer memberships may be enrolled. The canonical broker, Store, account and reference remain unchanged. The operation is add-only and does not refresh/login, create new accounts, remove profiles, rewrite existing auth, start models or invoke paid APIs.

New destinations must exist as owned, physically distinct, non-overlapping empty 0700 directories. Existing destinations and directory aliases are rejected. Current canonical/old profile fingerprints, owner authority, current project/member bindings, all target idleness and exact generation must match the plan. An exclusive broker lock excludes managed worker guards. All profile ownership claims and a durable enrolling intent are committed before the first credential copy. Each local atomic 0600 copy holds an immediate database authority fence, without external callbacks. Final checks commit the new binding, snapshots and next generation.

If a copy/crash/revocation/drift interrupts an intent, the broker is uncertain and new ownership claims remain reserved. Already copied credentials are not rolled back or overwritten from an old snapshot; replay is blocked. Recovery requires a separately reviewed, explicit reconciliation procedure. No automatic repair is implemented. Plan creation does not mutate credentials or reserve directories, so every condition is checked again at apply time.

Only the same authoritative Store coordinates profile ownership/roles, and only guarded profile use coordinates with the broker lock. Sharing these directories with another Store or unguarded CLI is unsupported. The supervisor should keep projects inactive while provisioning roles and enrollment; enrollment does not turn on maintenance or assign work. No actual enrollment was performed while developing this module.
