# 비공개 백업, 복구 및 인증 만료 확인

`GovernanceDurability(core)`는 서버에 등록된 동일한 `ThreeTier`/SQLite 저장소만 사용합니다. 파일 백업·복구는 HTTP 업로드, 아카이브 해제, 배포 또는 다른 호스트 구성 변경을 수행하지 않습니다. 전체 DB에는 여러 프로젝트의 사적 상태와 인증 해시가 있으므로 `projects == ['*']`인 전역 소유자만 백업·복구할 수 있습니다. 프로젝트 한정 소유자는 전체 DB를 내보낼 수 없습니다.

신뢰된 로컬 관리자 코드에서 아래 API를 호출합니다. 실제 토큰을 소스 파일, 명령행, 로그 또는 문서에 쓰지 않습니다. `owner_token`은 기존 비공개 인증 연결로 전달합니다.

```python
from manager_bridge.governance_durability import GovernanceDurability
recovery = GovernanceDurability(core)
receipt = recovery.backup(owner_token, '/private/backups/new-snapshot')
result = recovery.restore(owner_token, '/private/backups/new-snapshot',
                          '/private/recovery/new-manager.sqlite3')
```

백업 목적지의 부모는 현재 사용자가 소유한 비공개 디렉터리(권한 0700)여야 합니다. 백업 디렉터리는 새로 생성하며 기존 파일·심볼릭 링크를 덮어쓰지 않습니다. 결과는 0600 SQLite 파일과 0600 메타데이터 파일 두 개입니다. SQLite 온라인 백업은 커밋된 WAL 내용도 일관되게 복사하며 커밋되지 않은 변경을 포함하지 않습니다. 원본 WAL을 강제로 체크포인트하지 않습니다. 데이터 크기는 256 MiB, 메타데이터는 64 KiB, 백업 작업은 30초로 제한합니다. 메타데이터의 SHA-256, 스키마 digest, 리더 epoch 및 크기를 복구 전 검증합니다. 이 해시는 파일 간 일관성 확인이며 외부 서명이나 별도 보관장소의 신뢰 증명을 대신하지 않습니다.

복구 순서:

1. 기존 감독 프로세스와 새 감독 프로세스가 동일 작업을 중복 실행하지 않도록 관리자가 운영 전환 절차를 정합니다. 이 기능은 기존 작업자의 종료를 증명하지 않습니다.
2. 기존 DB와 구분되는 새 비공개 경로로 복구합니다. 목적지 DB 또는 WAL/SHM/journal이 이미 있으면 거절합니다. 원본 DB와 백업은 덮어쓰지 않습니다.
3. 반환 상태 `restored_requires_verification`과 `reconciliation_required: true`를 확인합니다. 이는 정상 운영 재개나 작업 성공을 뜻하지 않습니다.
4. 복구본의 실행 중 연속 관리자 동작은 `uncertain`/`restore_uncertain`으로 격리하며 기존 불확실 기록을 보존합니다. 리더 임대는 만료시키고 epoch를 증가시킵니다. 작업·보고·승인 기록을 재대기열로 바꾸지 않습니다. 복구 마커가 있는 동안 저장소의 실행 경로가 모두 차단되므로 대기 중 승인 작업도 실행되지 않으며 기존 임대로 보고·하트비트를 확정할 수 없습니다. 이 차단은 Core 또는 서비스 설정을 생략해 다시 시작해도 유지됩니다. 현재 자동 해제 또는 해제 API는 없습니다. 향후 명시적인 소유자 복구 검토 절차를 거쳐야 합니다. 기존 조정 절차로 실제 작업자 상태와 정확한 증거를 확인합니다. 알 수 없는 실행을 성공 또는 종료로 기록하지 않습니다.
5. 복구본은 기존 자격 증명 해시와 임대를 포함합니다. 원래 비공개 토큰 파일, Codex 프로필, OS 격리, 소스 연결 및 QA 제공자는 별도로 재검증해야 합니다. 백업은 원시 토큰 파일이나 Codex 자격 증명을 수집·복제·갱신하지 않습니다. 감독 프로세스를 자동 설치하거나 시작하지 않습니다.

`auth_watch(token, projects)`는 명시한 프로젝트의 등록된 관리자·개발자·리뷰어 연결을 확인합니다. 현재 토큰 권한, 부모 웹 세션의 만료·해제, 역할 및 설정 바인딩을 검증하며 출력은 회원 ID, 역할, 상태와 만료 시각뿐입니다. 인증 해시, 원시 토큰, 프로필 경로와 제공자 오류는 반환하지 않습니다. 기본 사전 알림 범위는 3600초입니다.

선택적인 신뢰된 `expiration_provider(project, role)`는 트랜잭션 밖에서 호출되며 프로젝트·역할마다 최대 한 번만 호출하며 정확히 `{'state': 'observed', 'expires_at': timestamp}`를 반환해야 합니다. Codex 프로필의 만료를 관찰할 수 없으면 `unavailable`입니다. 자격 증명이 만료·해제되었거나 곧 만료되면 `refresh_required`입니다. 프로필이 갱신되었다고 추측하거나 외부 갱신 API를 호출하지 않습니다. 제공자는 자체 제한 시간 안에 응답해야 합니다. 외부 관찰 뒤에 요청자의 권한과 회원 바인딩을 다시 검증합니다.

`queue_notices=True`는 소유자만 요청할 수 있습니다. 범위가 확인된 상태 변화의 중복 방지 키를 이용해 로컬 큐에 알림을 기록합니다. `list_notices(token, projects)`로 확인할 수 있으며 이메일·Slack·사용자 메시지를 보내지 않습니다. 알림 큐 기록 자체가 인증 갱신 또는 작업 실행 권한을 주지 않습니다.
