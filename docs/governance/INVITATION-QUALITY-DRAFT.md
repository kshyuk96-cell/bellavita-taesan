# 청첩장 자동 생성 기능의 승인 기준 초안

상태: **승인 전 제안**. 실제 기준 정책으로 등록하지 않았고, 운영 코드/상품/주문/기존 초대장을 변경하지 않았습니다. 아래는 요구사항 ID이며 외부 테스터의 시나리오 ID가 아닙니다. 실제 검증 시나리오와 연결해야 합니다.

| 요구사항 | 중요도 | 검토할 결과 |
|---|---|---|
| event-identity | P0 | 청첩장 원문의 신랑·신부, 혼주, 관계, 날짜·시간·장소가 잘못 바뀌거나 창작되지 않음. |
| invitation-pair | P1 | 93,500원용과 99,000원용 초대장 두 결과가 각각 생성됨. |
| order-pair | P0 | 각 초대장이 해당 가격의 서로 다른 주문 링크로 연결됨. |
| price-binding | P0 | URL/상품/주문서 가격이 서로 맞고, 임의 입력으로 가격이 바뀌지 않음. |
| approved-copy | P1 | 혼주 인사말과 서명은 실제 승인한 문구·표기 규칙을 따름. |
| approved-design | P1 | 실제 승인한 기준 이미지/문서가 제공된 뒤 모바일 가독성·배치·사진 반영을 비교. 자료를 보지 못했다면 미검증으로 보고. |
| product-snapshot | P1 | 예식별 사진·옵션·상품 정보 연결이 해당 행사와 일치함. |
| unknown-input | P1 | 필수 정보/연결이 모호하면 확인 필요로 남기며 성공·정상 결제로 표시하지 않음. |
| reproducible-delivery | P1 | 개발 결과, 독립 검토 결과, 실제 확인한 항목과 미확인 항목을 구분해 보고. |

실제 승인 자료의 retained reference ID·SHA256, 기준 버전, 외부 QA 계약/시나리오 매핑을 확보한 뒤 소유자가 초안을 승인해야 합니다. 과거에 공유한 주문 URL이 있다는 이유만으로 디자인 전체가 승인됐다고 간주하지 않습니다. 동일 기준을 전달해도 작업자별 결과가 자동으로 같아지는 것은 아닙니다.
