# Native subscription observations

`NativeSubscriptionObserver(core, guarded_host, member_id).read(actor, project)` performs only `account/read` with `refreshToken: false` and `account/rateLimits/read` with `excludeResetCreditDetails: true` and `supportsLunaReserve: false`. These methods/parameters were checked against the installed app-server generated JSON schema. No thread, turn, login, explicit token refresh, credit redemption or model invocation is implemented.

The host must carry a managed profile guard. Authority and current project configuration/member binding are checked before and after the native read. A changed binding, revoked actor or expired observation cannot return a usable observation. Native transport failures return `unavailable`; a trusted optional diagnostic callback receives only a fixed stage and categorical exception vocabulary. It never receives native error text.

Returned metadata has account scope, even though access is project scoped. It is not project expenditure, subscription token utilization or an execution authorization. Only primary/secondary used percentage, window duration and reset epoch are retained. Account IDs, email addresses, arbitrary labels, credits, balances and raw SDK responses are discarded. Missing windows are unavailable, never zero usage. Backend `ordinaryUsageAllowed: false` stays false even with zero usage; null remains unknown. Reset times and percentages cannot establish permission or automatic recovery. Observation freshness is at most 60 seconds and is not token expiry.

This read alone cannot authorize a worker: manager policy, explicit backend usage permission, current account/profile authorization and the worker's separate execution fences remain required. Profile ownership and guard coordination use the same authoritative Store; sharing profiles with independent Stores or unguarded CLIs is unsupported.

## Actual metadata proof

Private sanitized reports are under `/workspace/taesan-worker-links-subscription-proof` (mode 0700, reports 0600). The initial attempt stopped on a local import error before RPC; attempt 2 returned unavailable. One bounded authorized diagnostic retry (attempt 3) verified the broker guard and initialized app-server, then failed at `account/read(refreshToken:false)` with `TransportUnavailable`. Rate-limit reads were not reached and reviewer was not called. No raw exception text or credentials were persisted. No availability/quota success is claimed; ordinary usage permission is unknown. No models, paid API calls, explicit refresh, new login or profile redistribution occurred. Attempts 2 and 3 used the default network-restricted sandbox, so their connection failures do not establish bad credentials. A single supervising-coordinator-authorized corrected outbound read under escalated permissions succeeded for both managed profiles; `attempt-4/report.json` preserves the sanitized proof. Both reported `ordinaryUsageAllowed: true` and the same account-wide primary window: 14 percent used, 10080 minutes, reset epoch 1795390167. These observations expire after 30 seconds and do not independently authorize later execution. This adapter did not retry indefinitely.
