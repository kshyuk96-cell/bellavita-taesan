# 형님이 한 번에 확인할 실제 연결 패킷

개발 코드와 로컬 검증은 준비됐습니다. 아래 외부 권한·호스트가 연결돼야 실제 상시 운영·외부 복원 검증을 이어갈 수 있습니다. 90% 상시 통제 달성으로 보고하지 않습니다.

## 1. 비공개 복구 검증 저장소

현재 GitHub 연결은 저장소 읽기/기존 브랜치 쓰기는 가능하지만 새 저장소 생성 API는 403으로 거부했습니다. 기존 고객 저장소를 대신 쓰지 않았습니다.

[GitHub 새 저장소](https://github.com/new)에서 개인 계정 `kshyuk96-cell`의 `taesan-governance-recovery`를 **Private**, **README 포함**으로 생성하는 것이 최소 연결 조치입니다. GitHub 연결이 선택된 저장소만 허용한다면 새 저장소를 연결 허용 목록에 추가해야 합니다. 비밀번호/API 키 원문을 채팅에 보낼 필요가 없습니다.

연결되면 태산이가 ID·비공개 여부·main 브랜치를 확인하고, 합성 데이터로 생성→암호화→외부 저장→회수→원본 DB 없는 복원을 검증합니다. 현재 어댑터는 객체 1 MiB 이하 검증용이며, 고객 운영 백업/대용량 보관을 자동으로 시작하지 않습니다.

## 2. 상시 호스트 후보와 비용 범위

기존에 쓸 수 있는 전용 Linux VM이 있다면 새 VM 생성 없이 그 호스트부터 검증할 수 있습니다. 현재 연결된 Render 고객 서비스는 관리기로 전용하지 않습니다.

새 VM이 필요한 경우의 **후보**는 DigitalOcean Basic Regular의 2 vCPU / 4 GiB / 80 GiB SSD / 4000 GiB 전송 표기 모델입니다. [공식 가격표](https://www.digitalocean.com/pricing/droplets)를 2026-11-16에 직접 확인했으며, 표시 기본 요금은 **시간당 US$0.03571 / 월 US$24**입니다. 세금·환율·추가 옵션·초과사용 요금은 생성 전 별도 확인해야 합니다. 가격 조회만 했고 계정 생성·결제·VM 생성·추가 옵션 활성화는 하지 않았습니다. 이 가격은 성능·격리 자격 보증이 아닙니다.

후보 실행 방식은 Debian 계열의 **VM 위 일반 사용자 프로세스**입니다. 중첩 Docker 권한을 완화해서 통과시키지 않습니다. 먼저 개발 작업자 동시 실행 1개로 제한하고, unprivileged namespace 검사와 실제 작업 부하를 통과해야 확대합니다.

최초 연결 화면을 직접 처리할 경우의 후보 설정은 다음과 같습니다. **비용 범위를 확정한 뒤에만** 생성합니다.

- [DigitalOcean 대시보드](https://cloud.digitalocean.com/) → Create → Droplets.
- 공식 [지원 이미지 목록](https://docs.digitalocean.com/products/droplets/details/images/)에서 현재 확인한 **Debian 13** (`debian-13-x64`).
- Basic / Regular / 2 vCPU / 4 GiB / 80 GiB를 선택하고 생성 화면의 실제 요금을 다시 확인.
- SSH 인증에 준비된 **공개 키**만 추가. 유료 백업·추가 볼륨 등 옵션은 이 준비 패킷에서 켜지 않습니다.
- 생성 후 공급자 화면에서 확인한 서버 주소와 신뢰 가능한 호스트 키 지문을 연결. 그 전에는 태산이가 서버에 접속하거나 작업을 설치하지 않습니다.

이는 최초 접속을 위한 한 경로입니다. 공급자 API 권한을 연결하면 자원 수명주기 관리까지 자동화할 수 있지만, 현재 그 계정/권한은 제공되지 않았습니다.

신규 유료 호스트·운영 배포는 이전에 분리한 범위이므로, 호스트 계정 연결과 비용 범위 확인이 필요합니다. DigitalOcean 계정/VM 연결은 현재 이 세션에 없습니다. 승인만으로 클라우드 공급자의 인증이 생기지는 않습니다.

## 3. 비밀값 보관과 최초 접근

관리용 Ed25519 공개 키를 준비했습니다. 공개 키 파일은 `/workspace/taesan-transition-access/taesan-manager_ed25519.pub`, 지문은 `SHA256:A9nNQ0QXkefpfv/0gLbznYmh5u49IkB2FPNPmGClyQo`입니다. 비밀 키는 Git·채팅에 넣지 않고 작업공간의 별도 0700 디렉터리/0600 파일에 보관했습니다. 장기 키 보관/분실 복구가 확정됐다는 뜻은 아닙니다.

호스트가 준비되면 공급자 계정에서 이 공개 키로 최초 접근을 허용하고, 공급자의 신뢰할 수 있는 화면/채널로 호스트 키를 대조해야 합니다. 기존 구독 인증·백업 암호화 키·복구 서명 키는 별도의 보안 저장 경로/권한으로 연결해야 하며 원문을 채팅이나 Git으로 전달하지 않습니다. 현재 실제 외부 키 보관소는 연결되지 않았습니다.

## 연결 후 태산이가 이어갈 검증

1. 고정 커밋/독립 서비스 계정/사설 상태 경로 준비와 unit 초안 검토.
2. 기존 `check_governance_host.py identity`, `inspect`, `restart-proof`로 실제 호스트·격리·저장 측정.
3. owner-pinned HostAdmission, 복원 quarantine, 구독 한도/인증 및 소스 현재성 확인.
4. 중지→수집/검토 완료→서비스 종료/재시작→원본 없는 복원 확인. 실제 재부팅은 운영 전환 범위가 구체적으로 승인된 뒤 수행.
5. 외부 저장소 합성 왕복/서명 영수증/일회용 복구 승인 검증 후 한 프로젝트부터 제한 운영.

이 문서는 설치/배포 명령 실행 승인이 아닙니다. 현재 필요한 조치를 한 묶음으로 제시한 준비 패킷입니다.
