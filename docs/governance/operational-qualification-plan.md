# 90% 운영 검증 기준과 다음 10개 묶음

이 계획은 상시 운영 전환을 위한 기준이다. 개발 기능 수·테스트 수·등록된 계정 수를 전체 AI 능력 점수로 바꾸지 않는다. 기준 원본은 `ops/governance-operational-qualification.v1.json`이다. 각 체크포인트는 완전한 실행 증거가 있을 때 10점이며 부분 구현·오래된 관찰값·합성 시험만으로 점수를 주지 않는다. 90점 이상이고 모든 필수 체크포인트가 현재 운영 환경에서 검증돼야 목표 충족으로 보고한다. 이 계산은 실행 권한을 부여하지 않는다. 현재 운영 점수는 미산정이다.

## 승인된 이번 묶음

| 순서 | 결과물 | 완료 조건 |
|---|---|---|
| 1 | 운영 기준 | 버전·필수 조건·증거 형식·점수 산식을 고정 |
| 2 | 관리용 호스트 | 실호스트의 격리·사설 저장·코드 버전 검증 |
| 3 | 장기 인증 | 호스트 분실 뒤에도 독립 키 보관 경로로 복구 가능 |
| 4 | 역할 정리 | 승인된 중앙 범위와 기존·시험 역할의 수명주기 확정 |
| 5 | 서비스 설치 | 검토된 설정으로 서비스 설치·자동 시작 실제 확인 |
| 6 | 인증 만료 대응 | 사용 불가 시 차단하고 지원되는 재인증 후 회복 |
| 7 | 재시작 복구 | 상태 보존·불확실 작업 격리·중복 배정 방지 |
| 8 | 외부 복원 | 원본 관리 DB·호스트 없이 독립 복원 후 격리 |
| 9 | 제한 운영 | 한 프로젝트의 개발→독립 검토→인수→후속 지시 |
| 10 | 지속 관찰 | 최소 24시간 동안 예정 실행 대비 실제 결과·비용 검토 |

호스트·장기 인증·만료 대응·재시작 복구·외부 복원·제한 운영·지속 관찰은 필수 조건이다. 설정 문서·역할 정리·자동 시작 중 하나의 공백이 남아 90점인 경우에도 남은 공백을 별도로 보고한다. 실제 배포 전에는 해당 공백의 운영 영향을 검토해야 하며, 점수로 이를 자동 승인하지 않는다.

## 설치와 시험 순서

1. 기존 전용 Linux 호스트를 먼저 확인한다. 없으면 공급자·현재 요금·전체 비용 범위를 확인한 구성을 제안한다. 새 유료 자원은 그 구체적 범위가 승인된 뒤 생성한다. 기존 고객 서비스를 관리기로 전용하지 않는다.
2. 정확한 코드 커밋·일반 서비스 사용자·비공개 상태 경로·인증 보관 위치를 고정한다. 공유 인증 관리기의 전체 프로젝트 범위와 관리자의 범위를 대조한다. 시험 역할 추가·정리는 승인된 범위로 수행하며 등록 이력을 숨기지 않는다.
3. 고정된 코드를 설치하고 `check_governance_host.py`로 호스트 신원·격리·저장을 측정한다. `run_governance_service.py --preflight`와 `--status`를 사용해 설정 및 상태 조회를 확인한다. 전자는 예비 구성 점검이고 후자는 서비스 구성 단계까지 포함하므로 동일한 검증이 아니다.
4. 인증·암호화·복구 서명 키를 별도 보관 경로에 연결한다. 키 원문은 Git·채팅·로그에 넣지 않는다. 현재 계정 메타데이터의 짧은 유효기간을 OAuth 만료나 상시 접속 보증으로 해석하지 않는다.
5. 서비스 초안을 검토한 뒤 승인된 설치 범위에서 실제 서비스 관리자로 활성화한다. `--once`와 `--max-ticks`도 인증 조회·갱신·작업 배정을 수행할 수 있는 실제 실행이다. 읽기 전용 진단으로 취급하지 않는다.
6. 인증 실패·관리 프로세스 재시작·원본 없는 복원 시나리오를 각각 실행한다. 멈췄다는 증거가 없는 작업은 격리하고 자동 재실행하지 않는다. 외부 저장 성공과 키를 잃은 상태의 복구는 별개로 확인한다.
7. 소유자가 승인한 정확한 한 프로젝트·작업·비용 범위에서 제한 운영한다. 운영 데이터·결제·발송·배포 승인은 해당 작업의 범위에 따로 묶는다. 개발 산출물과 독립 검토 증거를 실제로 회수한다.
8. 최소 24시간 관찰한다. 구간·예약 주기·기대 횟수를 먼저 고정하고 실제 완료·누락·중복·불확실 작업·한도 사용을 대조한다. 늦은 성공 기록으로 누락이나 장애를 숨기지 않는다.
9. 검증자가 체크포인트별 증거 해시·호스트·코드 버전·시각·범위·한계를 검토한다. 오래된 자료는 갱신 전까지 미검증으로 처리한다. 고객이 이해할 수 있는 결과와 다음 10개 제안을 한 보고로 묶는다.

## 기존 실증의 범위

합성 장애 복원, 합성 백업의 외부 왕복, 실제 시험용 계정 메타데이터 조회, 임시 통합 관리자의 시작·상태 조회는 각각 해당 범위의 증거다. 운영 호스트·장기 키 보관·지속 운영의 인수 증거로 승격하지 않는다. 상세 실증 자료는 비공개로 유지한다. 이 문서에는 자격증명·운영 인프라 식별자·고객 소스 핀을 넣지 않는다.

## 이후 보고 규칙

각 묶음의 종료 보고에는 실제 완료·실행 검증·미확인 조건·필요한 사용자 조치와 다음 10개 제안을 포함한다. 사용자가 다시 묻기를 기다리지 않고 다음 묶음을 제시한다. 이 대화가 종료된 뒤에도 자동으로 개발이 계속된다고 약속하지 않는다. 지속 실행은 실제 호스트와 승인된 스케줄이 연결된 범위에서만 보고한다. 기존 시간별 개발·시트 점검·예약 배포 설정은 변경하지 않는다.
