# 배송 담당·일정·완료 사진·정산·연동 진단

기존 PR #20에서 이어서 구현했다. 운영 main 병합·Render 운영 배포·실거래·실발송·운영 시트 쓰기는 별도 범위다.

## 담당 배정과 인수인계

대표 카톡 명령 `쇼핑몰 관리`의 10분 유효 링크에서 주문을 펼쳐 등록 직원에게 배정한다.
기존 직원 승인 테이블과 환경의 승인 직원 목록을 사용한다. 등록 이름은 등록자가 입력한 이름으로 표시하며,
DB에 제한된 역할이 있으면 환경 목록보다 우선해 차단한다. 취소·배송 완료 주문은 담당 변경을 막는다.

배정 버전, 담당 직원 ID/등록명 스냅샷, 근거, 접근 경로, 시각을 보존한다.
배정 후에는 현재 버전에 서명된 `현재 담당자 주문 링크 (24시간)`를 사용한다.
이전 배정 링크와 이전 공용 배송 링크는 차단된다. 미배정 주문은 기존 공용 배송 링크를 유지한다.
POST 처리 직전 SQLite 쓰기 잠금 안에서 배정 버전을 다시 확인한다.
인수 확인은 해당 버전에서 한 번 기록한다. 취소/부분취소 미대조 주문은 인수를 막는다.

전용 링크는 주문·배정 버전에 대한 Bearer 권한이며, 실제 조작자의 실명 로그인을 증명하지 않는다.
감사 이력도 `assignment-link-vN`으로 남겨 등록 직원의 실명 인증과 구분한다.
직원 알림의 주문 링크는 현재 배정 링크를 사용하고 고객 알림에는 직원 관리 링크를 전달하지 않는다.

## 행사일 기준 일정표

한국 시간 행사 일시 오름차순으로 조회한다. 기본 최근 7일~앞으로 30일이며 최대 94일 범위다.
담당자·미배정·배송 단계·미완료 필터와 기한 경과/24시간 이내/보류 표시를 제공한다.
한 번에 2,000건을 넘으면 기간을 좁히도록 안내한다.
일정표 링크는 최근 목록 200건 밖의 주문도 `?order=고유주문번호`로 열 수 있다.
관리자 목록에도 전체 기록에서 정확한 고유 주문번호로 여는 기능을 추가했다.

## 배송 완료 사진과 고객 확인

1. 결제/잔액 대조가 유효한 배송 완료 주문에서 관리자 또는 현재 직원 링크로 업로드한다.
2. JPEG·PNG·WebP 정지 사진만 허용한다. 최대 5MB·2천만 픽셀·주문당 10개다.
3. 실제 이미지 디코딩·검증 후 EXIF 방향을 반영하고 1600px 이내 JPEG로 다시 저장한다.
   원본 파일명/경로·EXIF·위치 메타데이터를 공개 파일에 보관하지 않는다.
4. 같은 주문의 동일 정규화 사진은 중복 보관하지 않는다. 업로드 직후에는 고객 비공개다.
5. 관리자가 주문·사진·공개 범위를 확인해 공개하거나 숨긴다. 직원은 공개 결정을 할 수 없다.
6. 고객 상태 화면에는 공개된 해당 주문 사진만 보이고, 고객이 확인하면 사진 버전별 확인 시각을 기록한다.

사진은 공개 디렉터리 대신 `shop-delivery-photos/{주문번호}/{사진ID}.jpg`에 저장한다.
직원/관리자 열람과 고객 열람은 별도 HMAC 서명 URL이다. 고객 URL도 공개 상태·배송 완료·결제 상태를 매 요청 확인한다.
숨김/취소/부분취소 보류 후 이전 고객 URL은 차단된다. 파일 SHA-256이 바뀌면 응답을 중단한다.
고객 확인 POST는 주문·사진 ID·공개 버전·만료 시각에 묶인 서명과 Origin을 검증한다.
확인 행위는 `customer-order-link` 접근을 기록하며 구매확정/정산/결제 상태를 자동 변경하지 않는다.
사진 변경과 고객 확인 이력은 별도 테이블에 남는다. 자동 백업 복구 시험은 사진 파일과 DB 해시도 대조한다.

## 기간별 정산 Excel

관리자 화면에서 접수일 범위(한국 시간, 최대 367일)를 선택한다. 최대 10,000건이며 초과하면 기간 축소를 안내한다.
`주문정산`, `정산기준·합계` 시트에 주문번호, 담당자, 금융/배송 상태, 원주문금액, 승인원금,
취소 누계, 잔액, 미결제 주문금액, 페이앱 번호, 원장 ACK 고유 참조와 점검 메모를 담는다.

- **접수일 기준 주문의 현재 상태**다. 선택 기간 이후 취소도 내보내기 시점까지 반영한다. 거래일 기준 매출표와 구분한다.
- 부분취소 후 전체취소는 취소 누계를 원금으로 표시하며 이중 가산하지 않는다.
- 승인 전 요청취소(8/32)는 승인원금/금전 환불로 계산하지 않는다.
- 같은 주문의 재개/여러 ACK는 고유 원장 참조로 묶는다. 복수 참조나 서로 다른 주문이 공유하는 참조는 점검 대상으로 표시한다.
- 서버 ACK만 대조한다. 실제 운영 Google Sheets의 행 중복을 검증한 결과로 표시하지 않는다.
- 고객 입력 문자열은 Excel 수식으로 처리하지 않는다. 조회/내보내기는 원장·결제 테이블을 수정하지 않는다.

## 연동 설정 진단과 리포트

관리자 `설정·모의 연동 진단`에서 설정 유무와 HTTPS/시크릿 조건을 확인한다.
키 값·채널 ID 값·전화번호·시크릿 원문은 리포트에 담지 않는다. 누락된 환경 변수 이름과 상태만 표시한다.

모의 점검은 별도 임시 SQLite에서 합성 주문으로 실제 통보 처리 함수를 실행한다.
승인/중복 통보/부분취소 중복/전체취소 뒤 늦은 승인, 알림톡 템플릿·샘플 링크를 대조한다.
운영 DB에는 진단 결과 감사 행만 저장하며 외부 요청·발송·가맹점 거래는 실행하지 않는다.
런타임 검증은 Python 최적화 옵션에서도 생략되지 않도록 일반 조건 검사로 실행한다.
`live_payment`, `live_messages`, `live_cash_receipt`는 `not_run`으로 표시한다.
관리자 서명·만료 검증을 거친 JSON 다운로드를 제공한다.

## 보존과 운영 한계

새 배정/인수/사진/고객 확인/진단 테이블과 사진 파일은 기존 백업·복구에 포함된다.
등록 직원 설정·실가맹점 연결·카카오/MMS 실제 단말 수신·Render 운영 보존은 이번 검증 성공으로 간주하지 않는다.
