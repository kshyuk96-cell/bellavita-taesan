# 관리자 우선순위·응대·교대 개선

업무 우선순위(높음/보통/낮음)의 정렬·검색·변경 이력, 공유 응대 문구 템플릿과 주문 상태 치환·복사, 상품별 직원 운영 메모, 승인 정정을 먼저 보여주는 작업 핵심 정보와 접수 원본 접기, 담당자·기한으로 좁히는 교대 미처리 요약을 추가했다.

기존 업무 테이블에 우선순위 열을 추가하고 기본값은 보통으로 유지한다. 기존 내용·버전·금액·주문 상태는 변경하지 않는다. 적용 전 독립 검증 서버의 기존 데이터 백업·임시 복구를 통과했다. 템플릿·상품 메모는 버전 대조와 변경 이력을 보관하며 상품 메모는 가격·옵션·카탈로그 리비전을 바꾸지 않는다.

고객 템플릿은 허용 치환 항목만 사용하고 자동 발송하지 않는다. 고정 문구는 관리자가 검토한다. 내부 메모는 고객 요약/템플릿 치환에 넣지 않는다. 교대 요약은 직원 내부용으로 주문번호·업무·담당자·기한·내부 근거를 포함하고 고객 이름·전화번호는 넣지 않는다. 미처리만 최대 100개까지 표시하며 초과 시 조건을 좁히도록 안내한다.

회귀 155개와 집중 6개를 통과했다. 이전 9열 업무 DB의 반복 초기화 후 보존, 우선순위 정렬·필터·잘못된 값 거부, 템플릿의 잘못된 치환·충돌·사용 해제, 상품 메모 비공개·충돌·빈 메모, 교대 요약의 담당자/기한/100개 한도, 원접수 기록 접기를 확인했다.

375/1280px Chromium에서 우선순위 지정·검색, 템플릿 등록과 상태 치환, 메모 저장 시 상품 불변, 작업 핵심·원본 토글, 교대 조건 검색, 복사 미지원 대체 선택을 확인했다. JavaScript 오류와 가로 넘침 없음. 기존 일일 업무·교육, 저장 검색·인수인계·상품 비교·매뉴얼, 네 상품 고객 주문서도 통과했다.

검증 서버 배포·재배포 보존과 복구 결과는 `docs/validation/shop-admin-team.json`에 기록한다. 운영 병합·실거래·실발송·실제 영수증 발급·운영 원장 쓰기는 실행하지 않았다. 인증 링크와 비밀키는 기록에 남기지 않는다.

독립 Render 서버에 `e708eae` 배포 후 기존 업무의 보통 우선순위를 확인하고 모의 높은 우선순위 업무·응대 템플릿·상품 메모를 저장했다. 같은 코드로 재배포한 뒤 세 기록 보존, 고객 템플릿의 실제 주문 상태 치환, 내부 상품 메모의 쇼핑몰 비노출, 교대 담당자 필터, 기존 주문 3건의 결제 대기·취소 상태 유지를 확인했다. 영구 디스크·SQLite 무결성, 새 테이블 세 개의 백업·임시 복구 건수 대조, 배포 매뉴얼 원본 일치도 통과했다.
