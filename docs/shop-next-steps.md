# 미완료 검토와 다음 작업 제안

2026-11-14 기준. 기존 초안 PR #20 (`codex/shop-backend` → `main`)에서 계속 개발한다.
운영 main 병합·Render 운영 배포·실결제·실발송 활성화는 별도 요청 범위다.

## 완료한 승인 묶음

- 서버 저장형 샘플, 부분취소 잔액 대조 후 보류·재개.
- 첫 다섯 묶음: 알림톡, 제작 PNG/PDF, 버전별 검수, 운영 현황판, 자동 백업·복구 시험.
- 두 번째 다섯 묶음: 배송 담당·인수인계, 행사일 일정표, 배송 사진·고객 확인,
  기간별 정산 Excel, 비밀값 비노출 설정·모의 연동 진단.

전체 회귀 114개 통과. [이번 검증](shop-delivery-suite-validation.md)과
[배송 운영 안내](shop-delivery-suite.md)를 참조한다.

## 남은 범위

- 실가맹점 거래·국세청 반영·알림톡/MMS 실제 단말 수신은 미검증이다.
- 운영 Render 디스크 경로·재배포 보존·운영 자동 백업 활성화는 미검증이다.
- 실제 족자 장비 규격 확정·사진 자동 합성·프린터 실행·운영 Sheets 쓰기는 별도다.
- 사진 공개·고객 확인은 주문 서명 링크 권한을 사용하며, 조작자의 실명 로그인을 증명하지 않는다.
- 정산은 접수일 기준 현재 상태와 서버 ACK 참조 점검이다. 거래일 매출이나 실제 운영 시트 행 검증과 구분한다.
- 샘플 Site와 Python 백엔드는 별개다. Site의 배송 이미지는 명시된 합성 체험 이미지다.

설정 작업 완료 여부를 실거래·실수신 성공으로 기록하지 않는다.
일반 개발은 계정 설정을 기다리며 멈추지 않고 코드·모의·사본 검증을 완료한다.

## 다음 승인 제안: 다섯 건 묶음

1. **주문 내용 정정 승인**: 원주문을 보존하면서 정정 요청·승인 이력을 추가하고,
   승인한 문구·보내는 분의 새 제작 샘플 버전만 검수하도록 연결한다. 결제 금액은 자동 변경하지 않는다.
2. **재배송·AS 요청 관리**: 원주문번호에 요청 사유·처리 담당·진행 이력·추가 사진을 연결한다.
   실결제나 재출력은 자동 실행하지 않는다.
3. **일정 일괄 배정 사전 검토**: CSV 사본을 읽어 주문·행사일·담당자 불일치와 중복을 표시한 뒤,
   관리자가 승인한 유효 행만 배정한다. 결과를 내려받아 대조한다.
4. **상품·행사·중량별 판매 집계**: 승인·취소·잔액을 구분한 조회와 Excel 사본을 제공하고
   주문 정산 합계와 일치하는지 검증한다. 운영 시트에는 쓰지 않는다.
5. **운영 전환 사전 리허설**: 빈 독립 환경에서 상품 등록부터 주문·모의 결제·제작 검수·배정·배송 사진·정산·복구까지
   한 번에 재현하는 스크립트와 결과 보고서를 만든다. 운영 배포·실결제·실발송은 실행하지 않는다.
