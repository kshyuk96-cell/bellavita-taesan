# 미완료 검토와 다음 작업 제안

2026-11-14 기준. 초안 PR #20 (`codex/shop-backend` → `main`)에서 개발한다.
운영 main 병합·Render 운영 배포·실결제·실발송·실제 출력은 별도 요청 범위다.

## 이번까지 완료

서버 저장형 샘플, 결제/부분취소 대조, 알림톡/MMS, 제작 PNG/PDF·버전 검수,
공장 접수, 자동 백업/복구, 담당 배정·인수, 일정표, 배송 사진·고객 확인,
정산 Excel·진단에 이어 다음 다섯 건을 완료했다.

1. 원주문·금액을 보존하는 문구/보내는 분 정정 승인과 새 샘플 검수.
2. 원주문번호의 AS·재배송 요청, 담당자/처리 이력·비공개 추가 사진.
3. CSV 사전 검토, 승인한 최신 유효 행만 배정, 결과 다운로드.
4. 상품/행사/중량별 판매·취소·잔액 집계, 주문 정산 합계 대조·Excel 사본.
5. 두 가격 주문부터 서버·공장 복구까지 실행하는 독립 리허설.

회귀 126개, 모바일 흐름, 별도 리허설과 실제 샘플 호스팅 API를 검증했다.
[운영/재현 방법](shop-growth-operations.md), [검증 기록](shop-growth-validation.md).

## 남은 경계

- 실가맹점 거래·국세청 반영·실제 단말 수신, Render 운영 디스크/재배포/자동 백업은 미검증이다.
- 현재 제작 파일은 저장된 문구·보내는 분·중량의 텍스트 레이아웃이다.
  신랑신부 사진/상품 도안 자동 합성, 실제 장비 규격 확정·프린터 실행은 별도다.
- AS 처리는 업무 기록이며 결제·제작·실제 재배송을 자동 실행하지 않는다.
- CSV는 일정 일시를 대조하는 담당 배정이다. 행사 일시나 원주문 금액은 바꾸지 않는다.
- 정산·판매 집계는 접수일 기준 현재 승인/취소 상태이며 거래일 매출/실제 재고량과 구분한다.
- 운영 Sheets 쓰기는 연결하지 않았다. 서명 링크 권한은 실명 로그인 인증과 구분한다.
- Site는 별도 모의 체험이며 사진은 명시된 합성 이미지다. 실제 주문별 파일/사진 검증은 Python 백엔드다.

## 최신 승인 작업: 운영 준비 다섯 건

사용자가 승인한 범위는 대표 상품 UI/백엔드 통합, 관리자 편집, 독립 Render 환경, 페이앱 대조, 데이터 보존/복구다. 이 범위를 이전 제작/프린터 제안과 혼동하지 않는다.

코드 통합·관리자 편집·로컬/모의 연동·재시작/복구와 Render 계획 준비 결과는 [대표 상품 검증](shop-native-validation.md)에 기록한다. Render 계획 적용, 실제 마운트·재배포 후 기록 보존·백업/임시 복구까지 확인했다. [실환경 근거](validation/shop-native-render.json).

## 이번 승인 묶음 완료/경계

관리자 업무별 정돈, 외부 암호화 백업 Drive 저장·재다운로드 복구, 가맹점 테스트 준비, 알림톡 및 현금영수증 설정 진단을 진행했다. [실행 근거](validation/shop-operational-readiness.json), [운영 안내](shop-operational-readiness.md). 서버 자동 외부 업로드 인증·실가맹점·승인 알림톡 템플릿·상품 과세 구분은 미연결/미확정이며 실거래 성공으로 표시하지 않는다.

## 다음 제안 다섯 건

1. 주문 상세를 결제·제작·배송·알림 이력으로 정돈.
2. 상품 옵션 수정 뒤 기존 주문·발급 링크를 비교하는 관리자 검수 화면.
3. 백업 보관 기간·용량 현황과 외부 백업 누락 안내.
4. 알림 실패·결과 불명·재시도 대조 화면 개선.
5. 운영 전환 점검표와 담당자 인수 리허설.
