## 남은 범위

- 실제 가맹점 거래·국세청 반영·알림톡/MMS 단말 수신은 미검증이다.
- 운영 Render 디스크 경로·운영 재배포 보존·운영 자동 백업 활성화는 미검증이다.
- 제작용 텍스트 레이아웃과 검수 대기열은 구현했으며, 실제 족자 장비 규격 확정·사진 자동 합성·프린터 실행은 별도다.
- 운영 Sheets 쓰기는 연결하지 않는다. 원장 사본과 동일 주문번호의 제작 대기열을 사용한다.
- 샘플 Site는 서버 저장형 모의 체험이고 Python 운영 DB와 별개다. PNG/PDF 링크는 상품 기본 문구의 고정 예시다.

사용자 설정 작업 완료 여부를 실거래·실수신 성공으로 기록하지 않는다.
계정 설정을 기다리며 일반 개발을 멈추지 않고 코드·모의·사본 검증을 먼저 완료한다.

## 다음 승인 제안: 다섯 건 묶음

1. **배송 담당자 배정·인수인계**: 주문별 담당 직원과 변경 근거를 저장하고, 해당 주문의 직원 링크에서 확인한다.
2. **행사일 기준 제작·배송 일정표**: 행사 일시·현재 단계·담당자로 정렬해 기한이 가까운 미처리 주문을 찾는다.
3. **배송 완료 사진·고객 확인**: 사진 업로드·이미지 검증·권한별 열람을 구현하고, 동일 주문번호의 고객 화면에 연결한다.
4. **주문·취소·잔액 정산 파일**: 기간별 Excel 사본을 생성해 원금·취소 누계·잔액과 원장 중복 여부를 대조한다. 운영 시트에는 쓰지 않는다.
5. **외부 연동 설정 진단·검증 리포트**: 키 값을 노출하지 않는 설정 검사와 알림톡/PayApp 모의 점검을 제공하고, 실계정 검증과 모의 검증 결과를 구분한다.

## 승인과 보고 방식

앞으로 보고 끝에는 다음 작업 다섯 가지와 완료 기준을 제안한다.
사용자가 `ㅇㅇ`, `응`, `그래` 등 긍정으로 답하면 직전에 제안한 해당 다섯 작업을 승인한 것으로 이해한다.
완료·검증·한계를 구분하고, 별도로 제한한 운영 배포·실결제·실발송 범위를 자동으로 확장하지 않는다.
