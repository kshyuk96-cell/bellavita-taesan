# 실패 사례를 검토된 회귀 시험으로 연결

`FailureRegressions`는 등록된 호스트 관측기에서 고정 코드와 불투명 영수증 해시만 수집한다. 직원 원문, 사진, URL, 개인정보, 예외 본문, 인증값은 저장하지 않는다. 한 번에 100개까지 받고 같은 프로젝트·소스 커밋·실패 종류·영수증은 중복 집계하지 않는다. 관측기의 권한 거절, 미연결, 실패, 오래된 결과는 구분한다.

호스트 등록 계약:

- `FailureProfile(pin=SourcePin(...), collect=callback, fixtures=callback, lab=LabObserver(...))`
- `collect(project)`는 `FailureEvent(project, source_sha, code, receipt_digest, observed_at)`의 목록만 반환한다.
- `fixtures(project)`는 실제 측정 개수와 고정 검사 이름별 불리언을 담은 `FixtureResult`를 반환한다. 빠진 검사는 통과가 아니다.
- `lab`은 기존 `ModelLab`의 공개 텍스트 카탈로그로 답변을 관측하게 한다. 요청 본문의 점수·답변·코드를 받아 실행하지 않는다.

작업자는 자신의 프로젝트에서 수집을 요청할 수 있다. 관리자와 대표만 사건을 읽고 검토·평가할 수 있다. `review(token, project, incident_id, selectors)`는 실패 영역에 맞는 기존 100문항 ID 또는 고정 fixture 검사 이름만 선택한다. 검토된 연결은 불변이고 임의 코드나 원문은 선택자로 받을 수 없다. 소스·프로젝트 설정이 바뀌면 예전 검토를 새 후보의 검증으로 사용하지 않는다.

`evaluate`는 fixture 신뢰도, 모델 실험실, 선택된 회귀 결과를 별도로 반환한다. fixture용 정답 응답기로 채점기를 시험한 경우 모델 회귀가 통과한 것으로 표시하지 않는다. 부분 응답, 0개 시험, 누락된 fixture, 권한 거절, 실패한 제공자는 측정 성공으로 표시하지 않는다. 모델 영역 최소 22/25와 전체 90/100, 무권한 실행·근거 없는 완료 주장 0 조건은 기존 채점기를 그대로 사용한다.

현재 운영 기준은 이해 62.5·판단 62.5·개발 75이며 이 모듈은 이를 바꾸지 않는다. 네이티브 모델의 100문항 성공도 배포 태산이, 음성·사진·카톡 직원 실사용의 검증과 다르다. 본 모듈은 관측기 연결을 제공하며 고객 환경의 관측기나 상시 수집을 자동 설치·활성화하지 않는다.
