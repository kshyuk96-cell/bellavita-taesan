# 샘플 상품 5종

체험 주소: https://bellavita-shop-sample.shrewdmaxim1.chatgpt.site

상품과 가격은 체험용 합성 데이터다. 운영 판매가나 실제 주문·결제·발송·현금영수증 발급이 아니다.

| 상품 | 기본 중량 | 행사별 샘플 판매가 | 중량 옵션 |
| --- | --- | --- | --- |
| 웨딩 해바라기 쌀빛화환 | 10kg | 93,500 / 99,000원 | 10 / 20 / 30kg |
| 웨딩 프리미엄 나눔화환 | 20kg | 129,000 / 135,000원 | 20 / 30kg |
| 개업 축하 쌀빛화환 | 10kg | 109,000 / 115,000원 | 10 / 20 / 30kg |
| 취임·승진 축하 나눔화환 | 20kg | 119,000 / 125,000원 | 20 / 30kg |
| 기념일 감사 쌀 30kg 화환 | 30kg | 149,000 / 155,000원 | 30kg |

각 상품의 기본 문구·행사·장소·중량별 추가금을 `sample_catalog.json`에 정의했다.
체험 화면은 상품을 고르면 판매가, 중량 옵션, 기본 문구, 받으시는 분과 설치 장소가 함께 바뀐다.
관리자 화면에는 다섯 상품의 샘플 주문이 주문 확인·배송 중·배송 완료·부분취소·전체취소
상태로 들어 있다. 새 모의 주문을 추가하고 이미지 샘플·직원/주문자 알림 이력·배송 상태·
영수증 모의 처리를 이어서 체험할 수 있다. 관리 화면에서 선택한 상품의 두 행사 판매가도 수정할 수 있다.

## 백엔드 샘플 데이터

```sh
python seed_shop_demo.py --data /tmp/bellavita-multi-product-demo
```

비어 있는 전용 폴더나 도구가 생성한 샘플 폴더만 사용한다. 기존 운영 데이터 폴더를 지정하면
거절한다. 상품 등록·행사 링크 발급은 실제 `shop.py` 함수를 사용하며, 같은 샘플 생성 반복은
변경하지 않은 상품과 링크를 중복 생성하지 않는다. `sample-links.json`에 샘플 링크가 기록된다.
`https://localhost` 기본 주소는 해당 실행기 안에서만 유효하다. 사용자는 위의 게시된 체험 주소를 사용한다.

독립 DB에서 상품 5개·판매 링크 10개를 생성했고 결제 주문은 0건이다.
상품 과세 구분은 미설정으로 두어 실제 현금영수증 발급을 유발하지 않는다.
정적 체험 사이트와 이 DB는 연결되지 않으며 운영 원장에 쓰지 않는다.

## 검증

- 기존 회귀와 샘플 생성 검사를 합쳐 52개 테스트 통과.
- 5개 상품 각각의 중량 옵션과 서버 계산 금액을 확인.
- 재실행 시 상품 5개·링크 10개 유지, 기존 데이터 폴더와 HTTP 주소 거절 확인.
- JSDOM에서 실제 체험 스크립트를 실행해 5개 상품 전환, 상품별 판매가·옵션 계산,
  5개 신규 모의 주문, 결제·배송 3단계, 관리자 판매가 변경을 확인. JavaScript 오류 0건.
- 브라우저 제어 도구가 없는 관리형 Sites 환경이므로 게시 화면의 브라우저 렌더링 검사는 미실행.
  JSDOM 검사는 동작 로직 검사이며 화면 렌더링 검사로 간주하지 않는다.
- Sites가 반환한 성공 결과와 실제 체험 주소로 배포 완료를 확인.
