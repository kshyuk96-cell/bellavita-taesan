## 관리자 진입과 두 가격 링크

운영 코드의 관리자 진입 방법은 등록된 대표 계정에서 `쇼핑몰 관리` 명령이다.
10분 서명 링크가 나온다. 독립 데모에서는 `tests/serve_shop.py` 실행 시 관리자 링크를
출력하며 `/tmp/bellavita-shop-demo/test-links.json`에도 저장한다. 재시작하면 갱신된다.

이번 검증의 판매 링크는 다음과 같다. **실행기 내부 localhost 전용이며 공개 Render
테스트 URL이 아니다.** 다른 PC의 localhost에서는 열리지 않는다. 재현 방법은
[운영·검증 절차](shop-operations.md#독립-검증환경-재현)를 따른다.

| 가격 | 독립 테스트 주문 링크 |
| --- | --- |
| 93,500원 | https://localhost/shop/order/f03bd35c6c06d99776f1c2ed40684402 |
| 99,000원 | https://localhost/shop/order/fc7a5caf2825ca56abed17615cf547cd |

테스트 데모의 결제창 발급은 로컬 영수증으로 이동하는 모의 함수다. 고객 화면의 결제
버튼은 이 함수만 호출한다. 가맹점 API를 호출하지 않는다. 예식 사진도 로컬 테스트 이미지로
대체했다. 스크립트가 운영 환경 변수·가맹점 정보·모델·카카오 알림 설정을 테스트 값으로 덮어쓴다.

## 아직 검증하지 않은 항목과 필요한 조작

- Render 실제 `TAESAN_DATA`와 영구 디스크 마운트 관계: **미검증**.
  Render 도구가 작업공간 사용자 확인을 요구했고 선택된 작업공간이 없었다.
  조회 가능한 작업공간은 `Simba's workspace`이며 확인 질문을 남겼다.
  로컬 데이터는 `/tmp`이므로 운영용 영구 디스크 검증으로 간주하지 않는다.
- Render 플랫폼 재배포 후 보존: **미검증**. 위 재배포는 커밋 소스 교체 및 로컬 새
  프로세스 재기동이다. Render 운영 서비스의 재배포나 데이터 경로 변경은 하지 않았다.
- 테스트 가맹점/실제 결제·취소: **미검증**. 전용 가맹점의 테스트 수단·연동 설정·
  외부 HTTPS 통보 주소가 필요하다. 운영·검증 절차의 가맹점 대조 순서로 진행한다.
- 사용자가 실거래를 별도 승인할 경우 직접 테스트 결제와 전체/부분취소를 수행하고,
  동일 주문번호의 원결제·취소번호·금액·서명 통보·재전송을 서버 기록과 대조한다.
  해당 확인 전 운영 `SHOP_CHECKOUT_ENABLED`를 켜지 않는다.
- 모바일 검증은 Chromium이다. 실제 iOS Safari와 가맹점 앱 전환은 별도 단말 검증 대상이다.

운영 배포 승인에 필요한 작업공간·디스크·가맹점 정보가 준비되면
[운영 절차](shop-operations.md)에 따라 추가 확인할 수 있다.
