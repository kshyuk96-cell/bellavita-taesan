# 클라우드 중앙 제어 실행 준비

이 문서는 이미 승인된 로컬 코드의 실행 준비 절차입니다. 새 클라우드 자원, 요금제, 계정, 배포, DNS, 운영 데이터 또는 상시 실행 설정을 변경하지 않습니다. 실행 대상은 `bellavita-shop`, `bellavita-erp`, `hope-sunrise`, `funeral-association` 네 고객 프로젝트이며 **Tester 엔진의 개발·실행은 이 번들에서 제외**합니다. 이는 같은 문자열의 프로젝트명이나 외부 검증 계약을 보고할 수 없다는 뜻이 아닙니다. 개인 PC·회사 PC 연결은 이 클라우드 관리자 실행의 필수 조건이 아닙니다.

`ops/control-launch-preflight.json.example`은 검토용 증거 목록입니다. 런타임 설정으로 읽지 않으며 모든 관찰은 처음에 `not_verified`입니다. 파일을 복사하거나 항목을 작성하는 행위는 검증 완료나 소유자 업무 승인을 뜻하지 않습니다. 실제 증거와 확인 시각이 없는 항목은 미확인으로 남깁니다.

## 실행 경계와 비공개 상태

기존 승인된 클라우드 호스트에서 소유자만 접근할 수 있는 영속 볼륨을 사용합니다. 예시 경로는 `/var/lib/taesan/manager.sqlite3`입니다. 디렉터리는 현재 호스트 사용자 소유의 0700, DB·역할별 토큰·설정 파일은 0600으로 관리합니다. 컨테이너의 임시 파일시스템을 영속 저장소라고 간주하지 않습니다. 이 절차는 볼륨을 새로 만들거나 권한을 자동 변경하지 않습니다.

기존 `host.json`은 `ContinuousHost.load_host`가 읽습니다. 실제 깨끗한 애플리케이션 커밋, 분리된 프로젝트 소스/후보/런타임 경로, 개발자와 독립 리뷰어의 Codex 프로필, 고정 검사 명령, 등록된 역할 토큰을 검증해야 합니다. 전역 실행 한도와 프로젝트 한도, 기존 불확실 동작, 중지 확인이 없는 작업자는 그대로 실행 제한에 포함됩니다. 대시보드 표시가 멈췄다는 이유로 기존 작업자가 종료되었다고 기록하거나 새 작업자를 중복 실행하지 않습니다.

구독 프로필을 관리한다면 신뢰된 서버 구성이 `SubscriptionBroker`와 `subscription_host.attach_profile_guards(host, broker)`를 연결해야 합니다. 메타데이터 탐색, 개발 실행, 리뷰 실행 모두 해당 프로필 가드를 거칩니다. `build_service`는 신뢰된 Python 객체를 등록하며 HTTP나 JSON이 명령·모듈·콜백·프로필 경로를 선택하지 않습니다. 구독 갱신은 명시적인 주기, 같은 core/store의 브로커, 정확한 프로젝트 대상 집합, 소유자 권한 로더가 등록된 경우만 실행됩니다. UI 로그인이나 API 키 대체를 자동 시도하지 않습니다.

## 인증된 루프백 서비스

기존 비공개 호스트 설정과 별도로 아래 형태의 서비스 설정을 준비합니다. 토큰 값과 소유자 자격 증명을 JSON에 넣지 않습니다.

```json
{
  "version": 1,
  "host_config_file": "/var/lib/taesan/host.json",
  "listen": {"host": "127.0.0.1", "port": 8791},
  "governance": {},
  "supervision": {"auth_interval": 60, "health_interval": 30, "recovery_interval": 30}
}
```

기본 수신은 루프백이며 기존 인증·세션·CSRF 검증을 유지합니다. 외부 인터페이스에는 명시적인 HTTPS `public_origin`과 별도 검토된 역방향 프록시가 필요합니다. 여기서는 외부 수신, 프록시 또는 방화벽을 변경하지 않습니다. 서버로 등록된 소스 관찰·readiness·QA 제공자가 없으면 연결은 미구성/미확인이고 개발 실행을 차단합니다. JSON만 작성해서 네 고객 시스템이 연결되었다고 판단하지 않습니다.

프로세스를 시작하기 전 다음 명령으로 상태와 제한된 실행을 확인할 수 있습니다. 이미 같은 포트에 서비스가 실행 중이면 두 번째 감독 프로세스를 시작하지 않습니다. 별도 검토용 설정의 `port: 0`으로 격리한 smoke를 수행할 수 있습니다.

```bash
python scripts/run_governance_service.py --config /var/lib/taesan/governance.json --status
python scripts/run_governance_service.py --config /var/lib/taesan/governance.json --max-ticks 3
```

지속 실행의 진입점은 같은 스크립트에서 제한 옵션을 생략하는 것입니다. `ops/taesan-governance.service.example`은 감독 설정 초안이며 설치·활성화하지 않았습니다. 세 주기의 성공은 24시간 가동, 재부팅 후 복원, 비용 승인 또는 운영 배포 증거가 아닙니다. SIGTERM은 새 실행을 차단하고 수신을 종료하며 진행 중인 외부 작업의 종료는 별도로 확인합니다.

## 한 번의 사용자 요약

신뢰된 중앙 제어 객체는 `ControlDigest(portfolio, routing=..., supervision=...).report(token, projects)`를 호출할 수 있습니다. Portfolio는 한 번만 읽고, 소유자 결정을 만들기 위해 동일한 소스/QA 콜백을 다시 호출하지 않습니다. 추가 routing/supervision 조회는 등록된 서비스의 영속 상태 조회입니다. 보고 전후 요청자의 역할·프로젝트 범위·설정 바인딩을 확인합니다. 공유 감독 집계는 감독 전체 범위에 대한 권한이 있어야 조회할 수 있습니다.

요약은 현재 기술 승인이 확인된 표시 업무, 승인 이력만 있고 현재 확인되지 않은 업무, 차단 항목, 관찰이 없는 미확인 항목, 소유자 업무 배치·QA 정책 설정 결정을 구분합니다. 등록 사실을 완료로 세지 않고 임의의 90%/100%를 만들지 않습니다. QA 제공자 미구성은 외부 QA 계약·제공자 통합의 미완료로 표시합니다. Tester 엔진 개발이나 실행을 소유자 결정으로 만들지 않습니다. 배치 비용은 `not_measured`이며 추가 지출 권한을 주지 않습니다. 업무마다 별도 메시지를 보내지 않고 자동 외부 알림도 보내지 않습니다.

업무는 Portfolio의 전역 20건 창과 최대 세 건의 최신성 검사 범위를 따릅니다. 업무 커서는 인증된 `three-tier/overview`로 이어지며 digest가 자체 페이지를 자동 순회하지 않습니다. 배치는 프로젝트별 최신 20건입니다. 오래된 대기 배치 또는 권한상 생략이 있으면 `batch_window.partial`을 표시합니다. 소유자 결정 창 기본값은 20건이며 잘리면 `decision_window.partial`과 `summary_complete: false`를 반환합니다. 표시 창에 결정이 없다는 사실을 전체 승인 대기가 없다는 뜻으로 읽지 않습니다.

인증 만료 관찰은 갱신을 추측하지 않습니다. 백업은 별도 등록된 전역 소유자 로더와 비공개 목적지가 있을 때만 활성화됩니다. 보관 한도에 이르면 `retention_required`로 멈추며 기존·불명확 사본을 자동 삭제하지 않습니다. 실행 중/불확실 감독 동작은 주기가 지나도 재전송하지 않습니다. 복구본은 저장소의 영속 격리 마커로 실행이 차단되며, 현재 자동 해제 API가 없습니다. 상세 복구 절차는 `docs/governance/durability-restoration.md`를 따릅니다.
