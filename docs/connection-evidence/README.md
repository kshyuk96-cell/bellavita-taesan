개별 소스 테스트 합계는 **583 통과, 6 건너뜀**이다. 희망일출의 러너 요약 23은 파일 수이며 222 사례에 더하지 않는다. ERP는 새 체크아웃에서 `npm test`보다 빌드를 먼저 해야 한다. 협회 빌드에는 기존 동적 파일 탐색 경고 9개가 남았다. 소스 사본은 보안 격리 환경을 뜻하지 않는다. 외부 제공자는 모의 처리했고 실제 주문·결제·문자·카톡·시트 쓰기는 없었다.

`source-baselines.json`은 지정 커밋의 개발 시험 기록이다. 최신 원격 변경을 계속 추적한 결과가 아니다. 연결 관측기는 기록의 측정 시각을 보존하며 오래된 결과를 새 결과처럼 갱신하지 않는다. 원격/커밋·설정이 달라지면 재검증한다. ERP 운영 후보는 기존 RELEASE 규칙에 따라 추후 반영 직전 15분 내 시트 주문/참조 최신성과 충돌을 별도 확인해야 한다.

`native-model-lab.json`은 정답을 제공하지 않은 두 네이티브 개발 에이전트에 50문항씩 맡겨 수집한 관측 답변을 주 관리자가 채점한 결과다. 의도·조건·맥락·근거 각 25/25, 무권한 실행 선택/근거 없는 완료 주장 0이었다. 정확한 모델 ID와 운영 태산이 성능은 미확인이다. 운영 기준 점수 **이해 62.5 / 판단 62.5 / 개발 75**는 유지한다.

## 사용할 도구

- `python -m manager_bridge.manager_host`: 기존 비공개 상태와 고정 코드 검사. 기본은 리스너를 열지 않는다.
- `scripts/prepare_connection_review.py`: 이미 초기화된 비공개 등록부와 정확한 4곳 소스 사본으로 통합 연결 검토 패킷을 만든다. 미등록 연결은 성공으로 간주하지 않는다.
- `scripts/export_model_lab.py`: 합성 텍스트 평가의 공개 입력을 내보낸다. API 호출이나 키 생성은 하지 않는다.
- `deploy/project-onboarding/*.AGENTS.proposed.md`: 고객 저장소에 아직 설치하지 않은 제안이다. 기존 규칙을 대체하지 않는다.

## 형님께 묶어서 확인할 연결

1. PC에서 기존 개발 연결의 인증을 완료할 때 태산이 관리 수신기까지 등록한다. 기존 Codex 창은 소스 접근만으로 통제할 수 없다.
2. 전용 호스트의 후보 SHA·주소·요금·영구 저장소를 한 번에 검토한다. 현재 계획에는 비용 추정값을 임의로 넣지 않았다.
3. 각 고객의 소스·경로·필수 검사·위임 기간·작업 수를 고정한 설정을 적용한다. 기존 AI 게이트웨이를 먼저 확인하고 새 키가 필요한 경우에만 비공개 연결을 사용한다.

현재 실행 플래그는 4곳 모두 꺼져 있다. 이 문서와 연결 검토 패킷은 배포·개발 위임의 활성화가 아니다. 운영 변경은 해당 후보의 검증 및 기존 승인 범위에 따라 별도로 집행한다.

## 관리 코드 회귀

이번 후보의 전체 Python 회귀는 **723개 통과**했다. 신규 호스트·소스·연결·모델 관련 69개도 별도로 통과했다. 실제 네 소스 사본으로 통합 검토 CLI를 실행해 4곳 보고서를 만들었으며, 인증된 격리 작업 실행 준비 완료는 **0곳**으로 정확히 표시됐다. 고객 서비스의 운영 실행을 활성화하지 않았다.
