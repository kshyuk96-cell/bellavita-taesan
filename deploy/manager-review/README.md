# 전용 태산이 관리 호스트 배포 검토안

**미배포 제안**이다. 기존 벨라비타 운영 서비스와 네 고객 서비스는 변경하지 않는다.
`plan.json`의 후보 SHA, 호스트/지역/요금제/디스크/접근 범위가 확정되기 전 서비스를 만들지 않는다.
현재 요금이나 가용 플랜을 확인한 것으로 해석하지 않는다. 계획은 JSON이고 Blueprint에 연결하지 않았으므로 자동 인프라 동기화 경로가 없다.

관리 서버는 실제 작업 실행기가 아니다. 인증된 접수/위임/배정 API를 제공하더라도 등록된 소스 관측기·전송기·격리 실행기는 기본 미연결이며 네 프로젝트의 실행 플래그는 꺼진 상태다. 현재 CLI의 `/healthz`가 정상이어도 운영 준비나 고객 서비스 연결을 뜻하지 않는다.

## 시작 전 검토

1. 승인할 정확한 코드 커밋과 포함 PR을 고정한다. `--expected-commit`에 실제 40자리 SHA가 필요하며 다른 커밋·변경된 체크아웃이면 거부한다.
2. 기존 `manager_bridge.maintenance init`으로 별도 비공개 개발 상태를 준비한다. 공개 서버 시작 시 새 계정·키를 자동 생성하지 않는다. 관리자의 프로젝트 범위를 네 대상에 정확히 한정하고 대표·관리자 인증의 활성 상태를 확인한다.
3. 서비스에 영구 저장소를 승인받아 연결한 뒤 `/var/data/taesan-manager` 0700과 DB/인증 파일 0600을 준비한다. 자격 파일 내용을 문서·채팅·Git·로그에 넣지 않는다. 준비한 개발 상태를 안전하게 옮기는 실행은 별도 승인 범위다.
4. `maintenance.sqlite3`가 기본 DB다. 구형 `manager_bridge.server`의 `manager.sqlite3`는 `--database manager.sqlite3`로 **명시했을 때만** 사용한다. 자동 이름 추측·복사·변경은 하지 않는다. 둘 다 없거나 필요한 등록부/인증 스키마가 없으면 중단한다.
5. 실제 HTTPS 원점, 역방향 프록시, 새 관리 서비스의 플랜/디스크/예산/백업을 묶어 확인한다. 기존 운영 서비스 디스크나 요금제를 재사용·수정하지 않는다.

## 검토만 실행

```sh
python -m manager_bridge.manager_host \
  --source-root /app \
  --expected-commit APPROVED_40_CHARACTER_COMMIT \
  --persistent-root /var/data \
  --data /var/data/taesan-manager \
  --public-origin https://APPROVED_MANAGER_ORIGIN
```

위 자리표시자는 실제 승인값으로 바꿔야 한다. 기본은 검사만 하며 리스너를 만들지 않는다.
준비된 상태와 원점·커밋을 확인한 뒤에만 `--serve --host 0.0.0.0`를 붙인다. 포트는 `PORT`를 사용한다.
검사는 읽기 전용으로 DB/파일을 확인한다. 실제 시작은 기존 Store와 서버를 열지만 실행기·타이머·서비스·계정을 생성하지 않는다.

프로그램은 데이터가 선언한 영구 경로 아래에 있는지는 확인하지만 실제 디스크의 재시작 보존을 증명하지 않는다. 운영 승인 후 재시작 전후의 상태와 현재 미결 작업을 별도로 대조해야 한다. 복구는 프로세스를 중지하고 상태를 보존하는 것이며 DB·디스크·외부 실행을 자동 되돌리는 방식이 아니다.
